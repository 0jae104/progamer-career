# 11.1단계 결과: 덜 누르고 빨리 진행하기 (v0.11.1)

작성 2026-11-21. 대상 v0.11.0(`e6086bc`) → v0.11.1.

이 단계는 새 콘텐츠가 아니라, 소유자가 폰에서 직접 해 보고 말한 불편("화면이 직관적이지 않다, 창을 너무 오간다, 매달 돈을 다시 써야 한다, 진행이 답답하다, 여전히 재미없다")을 줄이는 작업입니다.

## 2. 바뀐 화면

## 3. 진행 버튼이 하는 일

- `N월 진행`: 정확히 한 달. 평범한 월간 보고는 창 없이 요약으로 남습니다.
- `다음 중요한 순간 ▶▶`: 아래 중 하나가 될 때까지 달을 넘깁니다.
  - 선택이나 확인이 필요한 창이 뜸(1-3 표의 "그대로 창" 전부)
  - 다음 달에 라이벌전이 있음(할 일을 바꿀 기회)
  - 컨디션이 40 아래, 손목이 30 아래로 **새로** 내려감
  - 12개월 또는 1.5초(한 번 누름의 상한)
- 멈춘 이유는 요약에 적힙니다. 대신 골라 주는 것은 없습니다. 창이 떠 있는 동안에는 두 버튼 모두 동작하지 않고, 연타해도 한 번만 진행합니다(검사함).
- 인위적인 대기 시간은 넣지 않았습니다.
- **예전의 "빠른 진행" 설정**은 "보고를 건너뛰기"와 "승부처·전략을 대신 고르기"가 한 스위치에 섞여 있었습니다. 이제 보고는 누구에게나 창 없이 나오고, 그 스위치는 "승부처·전략 맡기기"만 뜻합니다(기본 꺼짐, 기록·설정 탭). 예전에 켜 둔 사람은 켜진 채로 남습니다.

**같은 결과인가**: 진행 버튼은 사람이 "다음 달 → 확인"을 누르는 것과 같은 순서로 엔진을 부를 뿐이고 난수를 더 쓰지 않습니다. 커리어 60개를 손으로 한 달씩 넘긴 경우와 두 버튼으로 넘긴 경우(120회 비교)의 최종 상태·다음 난수 값이 모두 같았고, 멈춘 장면 10,348개의 종류와 순서가 같았습니다(건너뛴 중요한 장면 0).

## 4. 투자 자동 관리

- 플레이 탭의 자금 줄을 누르면 펼쳐집니다. 항목마다 스위치 하나와 "지금 사기".
  - 한 달에 한 번 항목(손목 물리치료, 심리 상담): **매달 자동**
  - 단계형(장비 세팅, 개인 코치, 식단·수면 관리): **모이면 자동**(한 달에 최대 한 단계. 최대 단계가 되면 스위치가 저절로 꺼짐)
- **실행 시점**: 매달 월급을 받은 직후 한 번. 같은 달에 두 번 실행되지 않도록 저장에 실행한 달을 적어 둡니다.
- **남겨 둘 돈**(기본 500만. 0 / 500만 / 2,000만 / 5,000만 중 선택)과 **한 달 상한**(기본 제한 없음. 500만 / 2,000만 / 5,000만). 사고 나서 남는 돈이 "남겨 둘 돈"보다 적어지면 사지 않습니다. 빚은 생기지 않습니다.
- **효과는 직접 살 때와 같습니다**(같은 함수). 그달에 이미 직접 산 항목은 자동으로 또 사지 않습니다. 손목 물리치료는 손목이 75 이하일 때만, 심리 상담은 이미 최대인 달에는 사지 않습니다("필요 없어 건너뜀").
- **기본은 전부 꺼짐**. 새 커리어도, 예전 저장도 직접 켜기 전에는 한 푼도 쓰지 않습니다.
- **알림**: 요약 줄에 "자동 관리 −220만", "자동 건너뜀 1건". "결과 자세히"에 항목별로 "심리 상담 −220만" 또는 "잔고 부족으로 건너뜀 / 한 달 상한에 걸려 건너뜀 / 이미 최대 단계 / 이번 달에 이미 삼 / 필요 없어 건너뜀".
- 새 투자 항목은 만들지 않았습니다.

### 검산 예 (헤드리스 크롬에서 화면을 눌러 10개월, `test/browser/play.js`)

심리 상담(매달 220만)과 장비 세팅(단계형)을 켜고 `N월 진행`으로 10개월: 자동 지출 합계 **1억 7,500만**, 같은 달 중복 구매 0, 잔고가 0 아래로 내려간 달 0, 장비 0 → 5단계(한 달에 한 단계씩, 최대가 되자 스위치가 꺼짐). 껐더니 다음 달부터 지출 없음. 잔고 300만·남겨 둘 돈 2,000만으로 맞춘 저장에서는 사지 않고 "자동 건너뜀 1건 / 잔고 부족으로 건너뜀"이 표시됨.

엔진만으로(`test/pacing.js`): 자동 관리가 실행된 170개월에서 산 것 458건, 건너뛴 것 1,038건(잔고 부족 849, 필요 없음 138, 최대 단계 51), 같은 달 중복 0, 음수 잔고 0, 매달 "쓴 돈 = 항목 합계" 일치, 상한 준수.

## 5. 저장과 기존 결과의 보호

- 저장 키 여섯 개와 `pg_opt_v1`은 그대로입니다. 포지션 ID(`van`, `rov`, `core`, `gun`, `sup`)도 그대로입니다.
- 커리어 저장 안에 선택 항목이 늘었습니다: `auto`(자동 관리 설정), `man`(이번 달에 직접 산 표시), `recap`(진행 요약), `lastRep`(지난달 보고). 없으면 없는 대로 열리고, 이상한 값은 `migrate()`에서 고치거나 버립니다.
- **자동 관리를 켜지 않으면 결과가 v0.11.0과 같습니다.** 커리어 400개(시드 12345)의 최종 상태 해시가 두 버전에서 `a4fbc3689d44a43f`로 같고, `node test/sim.js 3000 --seed=1`의 출력은 버전 줄 하나만 다릅니다. 자동 관리를 켜면 돈과 성장이 달라집니다(의도한 것. 직접 사는 것과 같은 효과).
- 예전 저장: `test/sim.js`의 예전 저장 22종 완주와 백업·복원, `test/browser/update-chain.js`의 v0.6.0~v0.11.0 → v0.11.1 실제 갱신(50개 확인) 통과.
- 예전 버전이 월간 보고 창을 띄운 채 저장한 파일을 열면 그 창을 그대로 보여 줍니다(몰래 넘기지 않음).
- 되돌리기: v0.11.1에서 진행한 저장(새 항목 포함)을 v0.11.0 엔진으로 열어 은퇴까지 진행됐고, 백업 파일이 v0.11.0의 검사를 통과했습니다. node에서만 확인했습니다.
- 이상한 값: 자동 관리·요약·지난달 보고에 엉뚱한 형식을 넣은 저장 6종이 안전한 값으로 열림. 문자열 삽입 검사(`security`)는 새 화면을 포함해 통과.

## 8. 하지 않은 것과 알려진 문제

- **손목 수치 삭제는 하지 않았습니다.** 손목은 부상 판정, 물리치료, 사건 문장, 예전 저장에 걸쳐 있어 한 번에 지우면 위험합니다. 이번에는 그대로 두었고, 불이익이 있는 수치를 숨기지 않으려고 커리어 탭에 계속 보이고 35 이하면 플레이 화면 위쪽에 경고가 뜹니다. 컨디션 하나로 합치는 것은 따로 옮기는 작업으로 제안합니다.
- **선택을 마친 뒤 자동으로 이어서 진행하지 않습니다.** 매번 직접 눌러야 합니다. "누르지 않은 버튼을 누른 것처럼 행동하지 않는다"를 지키려는 것이지만, 답답하면 옵션으로 넣을 수 있습니다.
- **사건이 자주 나옵니다**(달의 약 40%). "다음 중요한 순간"이 평균 1.5개월에서 멈추는 이유입니다. 여전히 느리다고 느끼면 가장 먼저 볼 곳입니다.
- 전체 누름 감소는 50%에 못 미칩니다(1-1).
- 요약은 직전 진행 한 번의 것만 남습니다. 그 전 달의 자세한 보고는 다시 볼 수 없습니다(소식 목록에는 한 줄씩 남음).
- "재미"를 직접 늘리는 것은 이번 범위가 아니었습니다. 마찰을 줄였을 뿐입니다.
