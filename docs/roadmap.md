# 개선 로드맵

피드백 문서(게임 개선 및 상업화 피드백)를 실제 코드와 대조한 결과와 단계별 계획입니다.
한 단계는 PR 하나로 끝내고, 매 단계 `node test/sim.js 3000`이 통과해야 병합합니다.

검토 방법과 한계

- 코드 전체(`js/data.js`, `js/engine.js`, `js/ui.js`, `css/style.css`)를 읽고 대조했습니다.
- 자동 커리어 3,000회를 은퇴까지 돌렸습니다(상태 검사 약 157만 회, 저장 왕복 약 3.7만 회).
- 화면은 폰 크기(390×844) 헤드리스 크롬에서 조작해 확인했습니다. 실제 폰 기기, iOS 사파리, 배포된 주소(github.io)에서는 확인하지 못했습니다. 글꼴도 테스트 환경에서 내려받지 못해 기본 글꼴로만 봤습니다.
- 사람이 플레이한 반응은 아직 없습니다. 재미, 난이도, 이탈 구간에 대한 내용은 코드와 시뮬레이션 수치에서 나온 추정입니다.

## 1. 피드백 항목별 구현 현황

| 피드백 항목 | 상태 | 실제 코드 |
|---|---|---|
| 연습생 → 2군 → 1군 → 국가대표 → 올해의 선수 | 구현됨 | `engine.js` `evaluateSquad`, `nationsMonth`, `offseason` |
| 능력치·잠재력·노쇠 | 구현됨 | 능력치는 6종(피지컬, 반응속도, 판단력, 팀워크, 멘탈, 숙련 폭). 한계는 `caps`, 노쇠는 `offseason`의 `fade` |
| 감독 신뢰, 부상, 이적, 연봉 협상, 은퇴 평가 | 구현됨 | `addTrust`, 손목 수치와 `injury`, `genOffers`, `negoP`, `evaluate` |
| 데이터·엔진·화면 분리, 자동 시뮬레이션 테스트 | 구현됨 | 파일 3개로 분리. `test/sim.js`는 1단계에서 확장 |
| 경기 시스템 | 일부 → 2단계에서 승부처 구현 | 빠른 시뮬레이션, 평점·KDA·경기 MVP 표시, 플레이오프·국제전의 경기 중 선택(`D.MOMENTS`, `runTour`). 하이라이트와 팬 반응은 없음 |
| 라이벌·스토리 | 미구현 → 4단계에서 구현 | 연습생 동기 2명이 성장·콜업·이적·은퇴하며 은퇴까지 유지됨(`S.rivals`), 라이벌 이벤트 17종, 실제 경기 결과 기반 전적 |
| 가상 SNS·팬 반응 | 미구현 → 5단계에서 팬 반응 구현 | 월간 보고 안에 그 달 경기 기록에 근거한 팬 반응 2~3줄(`D.FAN`, `fanReact`), 우승·라이벌 결승·이적·은퇴 뉴스 한 줄. 별도 SNS 화면은 없음 |
| UI/UX·연출 | 일부 | 모바일 한 손 조작 레이아웃은 있음. 온보딩, 승리 연출, 소리는 없음 |
| 반복 플레이 | 일부 | 포지션 5 × 성향 3 × 국적 4, 성장 카드 19종, 은퇴 별칭. 도전 과제와 해금 요소는 없음 |
| 구단·리그 생태계 | 일부 | 구단 전력이 매년 변하고 이적 제안이 옴. 이름 있는 NPC 선수, 이적 시장 소식은 없음 |
| 공유·기록 | 일부 | 명예의 전당은 기기 안에만 저장. 커리어 카드 이미지와 공유는 없음 |
| 수익화 | 미구현 | 광고·결제 코드 없음 |
| 이용 지표 측정 | 미구현 | 수집 코드 없음 |

피드백에서 바로잡을 점

- 예시에 나온 "미드", "바론"은 실제 게임의 용어입니다. 이 게임은 권리 문제를 피하려고 포지션과 용어를 따로 지었으므로(선봉, 유격, 코어, 사수, 지원) 경기 연출에도 실제 게임의 고유 명칭은 쓰지 않습니다.
- 능력치는 5종이 아니라 6종입니다.
- 확률 공개는 이미 있습니다. 선택 이벤트는 화면에 보이는 숫자로 그대로 판정합니다(`engine.js` `chance`, `resolve`). 경기 중 선택을 추가할 때도 같은 함수를 씁니다.

## 2. 발견한 문제

1단계에서 고친 것

| 문제 | 재현 | 위치 | 조치 |
|---|---|---|---|
| 진행 중인 커리어가 경고 없이 지워짐 | 타이틀 → 새 커리어 → 시작 | `ui.js` `start` | 한 번 더 눌러야 진행. 타이틀에 저장 요약 표시 |
| 저장이 손상되면 복구할 방법이 없음 | 저장 문자열이 잘리면 이어하기가 조용히 실패 | `engine.js` `load` | 시즌 시작마다 사본 저장, 손상 시 사본으로 복구, 손상본은 따로 보관 |
| 저장 형식이 바뀌면 예전 저장이 깨질 수 있음 | 새 필드를 추가한 뒤 예전 저장 열기 | `engine.js` | `migrate`에서 기본값을 채움. 이후 단계는 모두 이 함수를 거침 |
| 저장이 안 되는 브라우저에서 안내가 없음 | 사생활 보호 모드 등 | `engine.js` `store` | 타이틀과 게임 화면에 경고 표시 |
| 끝난 커리어도 "이어하기"로 표시 | 은퇴 후 타이틀로 이동 | `ui.js` `vTitle` | "지난 커리어 결과 보기"로 표시 |
| 시즌 기록의 소속이 승격 직후 값으로 남음 | 11월에 콜업된 해의 기록 | `engine.js` `offseason` | 그 시즌에 뛴 소속으로 기록 |

진행 불가, NaN, 범위를 벗어난 수치는 3,000회 시뮬레이션에서 나오지 않았습니다.

아직 남은 것(밸런스). 자동 진행 기준 수치이며, 사람은 더 잘합니다.

| 지표 | 값 | 판단 |
|---|---|---|
| 1군 데뷔 | 100% (평균 18.5세) | 초반에 실패할 여지가 없어 긴장이 약함 |
| 은퇴 나이 | 평균 31.7세 | 종목 특성에 비해 늦음. 후반 10년이 길게 늘어짐 |
| 1군 대회 우승 | 커리어당 2.95회 | 우승이 흔해 값어치가 떨어짐 |
| 포지션별 점수 | 지원 60.5 / 사수 51.3 | 반응속도 노쇠가 사수에게만 크게 작용 |
| 성향별 점수 | 두뇌형 57.8 / 노력형 52.1 | 노력형의 장점이 약함 |
| 부상 | 커리어당 0.59회 | 손목 관리가 거의 위협이 안 됨 |

밸런스는 수치만으로 정하면 안 되므로, 실제 플레이 반응을 받은 뒤 3단계와 묶어 조정합니다.

## 3. 이탈 위험이 있는 구간

- 첫 1~2년(연습생·2군): 경기가 없거나 의미가 작아 "계획 고르고 진행"만 반복합니다. 이 게임의 재미를 보여 주기 전에 20번 넘게 눌러야 합니다.
- 리그 달: 선택 없이 결과 표만 봅니다. 내가 키운 능력치가 경기에서 어떻게 작용했는지 보이지 않습니다.
- 20대 후반 이후: 능력치는 내려가고 새로운 사건이 줄어 같은 해가 반복됩니다.
- 첫 화면: 무엇을 목표로 무엇을 눌러야 하는지 알려 주는 안내가 없습니다.

## 5. 2단계 결과: 승부처

구현한 것

- 일반 리그 경기는 그대로 빠르게 처리합니다.
- 준결승·8강·4강은 시리즈가 마지막 세트까지 갔을 때 승부처가 1회 나옵니다.
- 결승은 어느 한쪽이 매치 포인트인 세트마다 나오며 시리즈당 최대 3회입니다. 결승에 출전하면 최소 1회는 나옵니다.
- 국제전(미드시즌 컵, 월드 파이널, 네이션스컵)에도 같은 기준을 씁니다.
- 상황은 14종(`D.MOMENTS`)이고 선택지는 3개씩입니다: 개인 기량(피지컬·반응속도), 판단(판단력·멘탈), 조직력(팀워크·숙련 폭). 보정이 큰 선택일수록 기본 확률이 낮습니다.
- 성공 확률은 이벤트와 같은 `chance()`로 계산해 그대로 보여 주고, 그 숫자로 한 번 판정합니다. 선택지마다 성공·실패 시 세트 승률도 표시하며, 이 값은 실제 세트 계산식(`effStr`, `winP`)에서 나옵니다.
- 성공해도 세트를 질 수 있고 실패해도 이길 수 있습니다(아래 수치).
- 빠른 진행을 켜면 기대 세트 승률이 가장 높은 선택으로 자동 판단합니다. 승부처 화면에서도 "감독 판단에 맡긴다"로 자동 선택할 수 있습니다.
- 벤치이거나 부상 중이면 승부처가 나오지 않습니다.

구조 변경

- `series()`를 없애고 대진과 진행 위치를 `S.sim.tour`에 두는 방식으로 바꿨습니다(`runTour`). 한 달 처리는 `simMonth`(시작) → `runSim`(대회 진행, 승부처에서 멈춤) → `finishMonth`(마무리)로 나뉩니다.
- 장면 종류 `moment`(선택), `mresult`(결과)를 추가했습니다.
- 판정은 선택하는 순간 한 번 일어나고 바로 저장됩니다. 선택 전에 다시 불러오면 같은 승부처가 같은 확률로 나오고, 결과 화면에서 다시 불러와도 세트가 다시 진행되지 않습니다.
- 우승·수상·시즌 기록 처리는 대회가 끝난 뒤 `tourEnd`에서 한 번만 실행됩니다.
- `migrate()`에 `sim`, `recentMom` 기본값을 추가했습니다.
- 리그 경기 계산식과 성장·계약 규칙은 바꾸지 않았습니다.

검증 결과 (`node test/sim.js 3000`, 실행 시간 약 58초)

| 항목 | 결과 |
|---|---|
| 커리어 3,000회 은퇴까지 진행 | 통과. 상태 검사 약 165만 회, 진행 불가·NaN·범위 이탈 없음 |
| 승부처 도중 저장 → 불러오기 → 재개 | 45,538회 모두 같은 승부처로 재개 |
| 결과 화면에서 반복 불러오기 | 세트 스코어와 경기 수가 변하지 않음 |
| 1단계에서 만든 실제 저장 4종(`test/fixtures`) | 각 20회씩 80회 모두 은퇴까지 진행 |
| 승부처 없는 리그 경기 | 승률 49.00% → 48.30%, 평균 평점 6.756 → 6.715, 평점 구간별 차이 최대 0.86%p (기준 1%p 이내). 실행마다 승률이 48.3~48.8% 사이에서 달라짐 |
| 표시 확률과 실제 성공률 | 개인 기량 51.3% → 51.1%, 판단 60.1% → 59.9%, 조직력 59.5% → 59.6% (기준 2%p 이내, 넘으면 테스트 실패) |
| 승부처 세트 승률 | 성공 뒤 표시 67.9% / 실제 68.0%, 실패 뒤 표시 35.3% / 실제 34.9% |
| 1군 대회 우승 | 커리어당 3.00 → 3.42 (+14%, 기준 +20% 이내) |
| 폰 크기 390×844 헤드리스 크롬 | 1단계 저장으로 이어하기 → 승부처 → 새로고침 후 같은 승부처 → 결과 → 새로고침 → 월간 보고까지 확인. 가로 넘침·스크립트 오류 없음 |

처음 구현에서는 선택 성공률이 63~72%여서 1군 대회 우승이 29% 늘었습니다. 모든 선택지의 기본 확률을 12 낮춰 위 수치로 맞췄습니다.

확인하지 못한 것

- 실제 폰 기기, iOS 사파리, 삼성 인터넷, 배포된 주소(github.io)
- 웹 글꼴이 적용된 화면(테스트 환경에서 글꼴을 내려받지 못함)
- 사람이 직접 했을 때 선택이 재미있는지, 문장이 자연스러운지

남은 문제

- 자동 진행 기준으로 우승과 올해의 선수가 조금 늘었습니다(올해의 선수 경험 10.4% → 12.4%). 3단계 밸런스 조정에서 함께 다룹니다.
- 시리즈의 킬/데스/어시스트는 세트 합계로 표시되어 단판 경기보다 크게 보입니다.
- 승부처는 내가 출전한 시리즈의 51%에서 나옵니다. 준결승이 2-0으로 끝나면 나오지 않습니다.
- 같은 상황이 최근 6회 안에 반복되지 않게 했지만, 14종이라 긴 커리어에서는 다시 보게 됩니다.

## 5-1. 3단계 결과: 초반 구간과 밸런스

측정 방법

## 5-2. 4단계 결과: 라이벌

구현한 것

- 새 커리어를 시작하면 같은 날 입단한 연습생 동기 두 명이 생깁니다. 한 명은 나와 같은 포지션, 한 명은 다른 포지션입니다.
- 라이벌은 고유 ID, 아이디, 포지션, 성향, 성장 유형(조숙·보통·대기만성), OVR과 잠재력, 소속 구단과 스쿼드, 상태(부상·부진·은퇴), 전적, 관계, 사건 기록을 가집니다.
- 리그 전체를 시뮬레이션하지 않고 라이벌만 가볍게 진행합니다: 매달 성장과 부상, 스플릿 종료와 스토브리그에 콜업 심사(선수와 같은 기준), 스토브리그에 노쇠·부진·방출·이적·은퇴.

| 1군 | 이적 소식, 맞대결 전날, 경기 뒤 복도(이긴 뒤), 진 날 밤(진 뒤), 같은 유니폼(같은 팀), 플레이오프 재회 한 줄, 결승의 라이벌 화면 |
| 후반 | 라이벌의 부진, 돌아온 라이벌, 라이벌의 은퇴, 가장 기억에 남는 상대, 은퇴 화면의 회고 |
| 예전 저장 | 눈에 밟히는 이름(라이벌이 없는 커리어가 1군에서 뛸 때 리그의 맞수가 생김) |

- 선택마다 경쟁심·존중이 바뀌고 결과 화면에 표시되며, 라이벌 카드의 "함께한 기록"에 남습니다.
- 관계는 이후 사건의 조건이 됩니다(부탁은 존중 30 이상, 새벽 연습실은 경쟁심 25 이상). 은퇴 화면의 회고 문장은 실제 전적과 관계에서만 만들어집니다.
- 콜업·이적·맞대결 결과·부진·복귀·은퇴에 대한 사건은 그 일이 올해나 지난해에 실제로 일어났을 때만 나옵니다. 결승 화면은 실제로 결승에서 만났을 때만 나옵니다.
- 이벤트가 나올 때 라이벌 이벤트를 고르는 비율을 제한했고(`rivalEventShare` 0.3, 방금 일어난 일은 `rivalNewsShare` 0.6), 사건마다 커리어당 최대 횟수가 있습니다. 최근 7개 중복 방지도 그대로 적용됩니다.

전적 규칙

- 내가 출전한 공식전에서, 상대 구단의 같은 리그 로스터에 부상이 아닌 라이벌이 있을 때만 기록합니다(`rivalMatch`).
- 리그 경기는 경기마다, 시리즈는 마지막 세트가 끝나 결과가 확정될 때 한 번 기록합니다. 승부처 도중에는 기록하지 않습니다.
- 경기 ID(`연차-월-라운드` 또는 `연차-월-대회·순번`)를 라이벌마다 보관해 같은 경기를 두 번 세지 않습니다.
- 같은 구단이면 기록하지 않습니다. 스크림과 새벽 연습실은 전적에 들어가지 않고, 화면에도 그렇게 적혀 있습니다.

화면

- 능력 탭에 라이벌 카드: 아이디, 포지션, 성향, 나이, 소속과 상태, OVR, 상대 전적, 경쟁심·존중, 관계, 최근 소식, 함께한 기록(펼치기). 탭은 늘리지 않았습니다.
- 홈에 이번 달 라이벌전 안내 한 줄(일정에 라이벌의 팀이 있을 때), 월간 보고의 해당 경기에 "라이벌전"과 라이벌 평점 표시, 승부처 화면에 상대 팀 라이벌 표시.
- 추가로 눌러야 하는 화면은 결승에서 만났을 때의 한 장뿐입니다.

저장

- 저장 버전 번호는 그대로이고 `migrate()`가 `rivals`, `rivalSeq`, `evn`을 채웁니다. 게임 버전은 0.4.0입니다.
- 예전 저장에는 라이벌이 없습니다. 연습생 시절 기록을 지어내지 않고, 1군에서 뛰기 시작하면 "눈에 밟히는 이름" 사건으로 리그의 맞수가 한 명 생겨 그때부터 기록이 쌓입니다.
- 라이벌 데이터가 없거나 손상돼 있으면 고칠 수 있는 것은 고치고(구단, 수치 범위, 빠진 필드) 고칠 수 없는 항목은 버립니다. ID가 겹치면 하나만 남깁니다.

남은 문제 (우선순위 순)

1. 자동 진행은 무난한 선택을 주로 골라 관계가 "벗"(48%)과 "호적수"(23%)에 몰리고 "앙숙"은 거의 나오지 않습니다. 사람이 도발 쪽을 골랐을 때 관계가 얼마나 빨리 갈리는지는 재 보지 못했습니다.
2. 결승에서 라이벌을 만나는 커리어는 4.5%입니다. 드문 것이 맞지만, 체감상 너무 드물면 라이벌이 강팀으로 옮기는 확률(`rivalAmbition`)을 올려 조정할 수 있습니다.
3. 라이벌의 80%가 나보다 먼저 은퇴합니다(평균 26.8세). 커리어 후반 4~5년은 라이벌 없이 지나갑니다.
4. 라이벌은 자기 나라 리그에만 있습니다. 내가 해외로 옮기면 만나지 못합니다.
5. 예전 저장의 맞수는 한 명이고 나와 같은 포지션입니다.
6. 라이벌 문구는 조사가 어긋나지 않게 "{이름}의, {이름}에게, {이름}도" 꼴만 썼습니다. 새 문구를 추가할 때도 같은 규칙을 지켜야 합니다.
7. 라이벌의 우승은 구단이 스플릿 우승을 했을 때만 기록되고 국제 대회는 반영하지 않습니다.

## 5-3. 5단계 결과: 팬 반응

구현한 것 (버전 0.5.0)

- 경기가 있던 달의 월간 보고에 팬 반응이 2~3줄 붙습니다. 새 화면과 추가 클릭은 없습니다.
- 문장은 그 달 경기 기록에서 확인되는 사실에만 붙습니다: 그 달 승패, 평균 평점, 경기 MVP, 높은 평점의 패배, 낮은 평점의 승리, 3연승·3연패 이상, 라이벌전 승패(라이벌 이름·양쪽 평점·통산 전적), 승부처 성공·실패, 플레이오프·결승 승패, 1군 데뷔전, 벤치.
- 경기가 없는 달(연습생, 휴식기, 스토브리그)에는 반응이 나오지 않습니다. 출전하지 못한 달에는 벤치에 대한 반응만 최대 2줄 나옵니다.
- 말투는 응원·쓴소리·분석·기대 네 가지이고, 한 달 안에서 겹치지 않게 고릅니다. 쓴소리는 경기 내용만 다루고 인신공격은 없습니다.
- 문장 틀은 `js/data.js`의 `D.FAN`(20분류 139개)에 있고, 선택 규칙은 `js/engine.js`의 `fanFacts`, `fanReact`입니다.
- 선택에 난수를 쓰지 않습니다(아이디·연차·월로 만든 값으로 고름). 같은 기록이면 같은 문장이 나오고, 경기 결과에는 영향이 없습니다.
- 같은 문장은 출전 10경기 안에 다시 쓰지 않습니다. 쓸 문장이 없으면 다른 사실의 문장을 쓰거나 줄 수를 줄입니다.
- 이름 뒤 조사는 받침에 따라 달라지지 않는 꼴만 씁니다("{nick}의, {nick}에게, {nick}도, {opp}전, {rival} 상대로"). 숫자 뒤에도 조사를 붙이지 않습니다.
- 값이 없는 자리가 있는 문장은 쓰지 않습니다(예: 통산 전적이 없으면 전적을 말하는 문장을 건너뜀).

뉴스 한 줄 (선택 기능, 핵심 검증 뒤 추가)

- 이미 있는 화면에 사실로만 만든 한 줄을 붙였습니다: 우승 화면(팀, 대회, 결승 스코어와 내 평점), 결승의 라이벌 화면(누가 이겼는지), 은퇴 화면(나이, 1군 경기 수, 우승 횟수), 1군 이적 시 소식 목록.
- 별도 SNS 화면, 실시간 커뮤니티, 외부 API는 없습니다.

저장

- 저장하는 것은 `S.fan` 하나입니다: 출전 경기 수, 연승·연패, 최근에 쓴 문장 ID(10경기가 지나면 지움, 최대 수십 개). 문장 자체는 저장하지 않고 월간 보고에만 실립니다.
- 예전 저장에는 이 값이 없어 처음부터 셉니다. 값이 깨져 있어도 처음부터 셉니다.
- 저장 버전 번호는 그대로입니다.

| 320px에서 목표 안내가 화면 아래로 밀려 하단 버튼에 가려짐 | 안내를 카드 제목 바로 아래로 옮기고 문장을 줄임. 가려져 있으면 한 번만 보이는 곳으로 스크롤 |
| 화면 전체에 읽어 주기 표시를 달면 다시 그릴 때마다 전부 다시 읽음 | 현재 상태 줄에만 표시 |
| 경기 목록의 상대 설명 글자가 10.8px | 12px로 올림 |
| 주 버튼의 흰 글자 명암비 3.2:1 | 어두운 글자로 변경(6.1:1) |

확인하지 못한 것

- 실제 폰(안드로이드 크롬, iOS 사파리, 삼성 인터넷). 위 결과는 모두 PC의 헤드리스 크롬에서 화면 크기만 맞춘 것입니다. 노치·하단 바 여백, 손가락으로 누르는 느낌, 사파리의 `inert`·`scrollbar-gutter` 동작은 보지 못했습니다(`inert`는 사파리 15.5 이상에서 지원, 그 이전에는 뒤 화면에 초점이 갈 수 있음).
- 화면 읽기 프로그램(톡백, 보이스오버)으로 실제로 읽히는 내용
- 웹 글꼴이 적용된 모습(작업 환경에서 글꼴을 내려받을 수 없어 대체 글꼴로 측정했습니다. 글자 폭이 달라 줄바꿈 위치가 다를 수 있습니다)
- 배포된 주소에서의 동작과, 0.5.0을 쓰던 기기가 0.6.0으로 넘어가는 과정(서비스 워커 갱신)
- 은퇴까지 사람이 직접 해 보는 플레이. 자동 정책으로만 돌렸습니다.

## 5-5. 다음 작업 제안: 7단계 커리어 카드와 도전 과제

넘어갈 수 있습니다. 근거: 6단계는 표시만 바꿔 5단계와 결과가 같고, 예전 저장 22종이 그대로 열립니다. 다만 7단계는 이미지 저장이 브라우저마다 달라서, 시작 전에 실제 폰에서 6단계를 한 번 확인해 두는 것이 좋습니다.

- 커리어 카드: 은퇴 화면을 이미지 한 장으로(캔버스에 직접 그림, 외부 라이브러리 없음). 저장 버튼과, 지원하는 기기에서는 공유 버튼.
- 도전 과제: 기기에 쌓이는 목록(예: 첫 1군 데뷔, 무관으로 은퇴, 월드 우승). 판정은 은퇴 기록만 읽으므로 경기 결과에 영향이 없습니다.
- 변경 파일 예상: `js/ui.js`, `css/style.css`, `js/data.js`(과제 목록), `js/engine.js`(판정과 기기 저장), `test/sim.js`
- 위험: iOS 사파리의 이미지 저장 방식, 캔버스에서 웹 글꼴이 늦게 적용되는 문제
