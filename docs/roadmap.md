# 개선 로드맵

피드백 문서(게임 개선 및 상업화 피드백)를 실제 코드와 대조한 결과와 단계별 계획입니다.
한 단계는 PR 하나로 끝내고, 매 단계 `node test/sim.js 3000`이 통과해야 병합합니다.

검토 방법과 한계

- 코드 전체(`js/data.js`, `js/engine.js`, `js/ui.js`, `css/style.css`)를 읽고 대조했습니다.
- 자동 커리어 3,000회를 은퇴까지 돌렸습니다(상태 검사 약 157만 회, 저장 왕복 약 3.7만 회).
- 화면은 폰 크기(390×844) 헤드리스 크롬에서 조작해 확인했습니다. 실제 폰 기기, iOS 사파리, 배포된 주소(github.io)에서는 확인하지 못했습니다. 글꼴도 테스트 환경에서 내려받지 못해 기본 글꼴로만 봤습니다.
- 사람이 플레이한 반응은 아직 없습니다. 재미, 난이도, 이탈 구간에 대한 내용은 코드와 시뮬레이션 수치에서 나온 추정입니다.

## 1. 피드백 항목별 구현 현황

| 피드백 항목 | 상태 | 실제 코드 |
|---|---|---|
| 연습생 → 2군 → 1군 → 국가대표 → 올해의 선수 | 구현됨 | `engine.js` `evaluateSquad`, `nationsMonth`, `offseason` |
| 능력치·잠재력·노쇠 | 구현됨 | 능력치는 6종(피지컬, 반응속도, 판단력, 팀워크, 멘탈, 숙련 폭). 한계는 `caps`, 노쇠는 `offseason`의 `fade` |
| 감독 신뢰, 부상, 이적, 연봉 협상, 은퇴 평가 | 구현됨 | `addTrust`, 손목 수치와 `injury`, `genOffers`, `negoP`, `evaluate` |
| 데이터·엔진·화면 분리, 자동 시뮬레이션 테스트 | 구현됨 | 파일 3개로 분리. `test/sim.js`는 1단계에서 확장 |
| 경기 시스템 | 일부 → 2단계에서 승부처 구현 | 빠른 시뮬레이션, 평점·KDA·경기 MVP 표시, 플레이오프·국제전의 경기 중 선택(`D.MOMENTS`, `runTour`). 하이라이트와 팬 반응은 없음 |
| 라이벌·스토리 | 미구현 | 이름 없는 일회성 이벤트 "라이벌의 도발" 하나뿐. 인물이 유지되지 않음 |
| 가상 SNS·팬 반응 | 미구현 | "악성 댓글", "팬레터" 이벤트만 있음 |
| UI/UX·연출 | 일부 | 모바일 한 손 조작 레이아웃은 있음. 온보딩, 승리 연출, 소리는 없음 |
| 반복 플레이 | 일부 | 포지션 5 × 성향 3 × 국적 4, 성장 카드 19종, 은퇴 별칭. 도전 과제와 해금 요소는 없음 |
| 구단·리그 생태계 | 일부 | 구단 전력이 매년 변하고 이적 제안이 옴. 이름 있는 NPC 선수, 이적 시장 소식은 없음 |
| 공유·기록 | 일부 | 명예의 전당은 기기 안에만 저장. 커리어 카드 이미지와 공유는 없음 |
| 수익화 | 미구현 | 광고·결제 코드 없음 |
| 이용 지표 측정 | 미구현 | 수집 코드 없음 |

피드백에서 바로잡을 점

- 예시에 나온 "미드", "바론"은 실제 게임의 용어입니다. 이 게임은 권리 문제를 피하려고 포지션과 용어를 따로 지었으므로(선봉, 유격, 코어, 사수, 지원) 경기 연출에도 실제 게임의 고유 명칭은 쓰지 않습니다.
- 능력치는 5종이 아니라 6종입니다.
- 확률 공개는 이미 있습니다. 선택 이벤트는 화면에 보이는 숫자로 그대로 판정합니다(`engine.js` `chance`, `resolve`). 경기 중 선택을 추가할 때도 같은 함수를 씁니다.

## 2. 발견한 문제

1단계에서 고친 것

| 문제 | 재현 | 위치 | 조치 |
|---|---|---|---|
| 진행 중인 커리어가 경고 없이 지워짐 | 타이틀 → 새 커리어 → 시작 | `ui.js` `start` | 한 번 더 눌러야 진행. 타이틀에 저장 요약 표시 |
| 저장이 손상되면 복구할 방법이 없음 | 저장 문자열이 잘리면 이어하기가 조용히 실패 | `engine.js` `load` | 시즌 시작마다 사본 저장, 손상 시 사본으로 복구, 손상본은 따로 보관 |
| 저장 형식이 바뀌면 예전 저장이 깨질 수 있음 | 새 필드를 추가한 뒤 예전 저장 열기 | `engine.js` | `migrate`에서 기본값을 채움. 이후 단계는 모두 이 함수를 거침 |
| 저장이 안 되는 브라우저에서 안내가 없음 | 사생활 보호 모드 등 | `engine.js` `store` | 타이틀과 게임 화면에 경고 표시 |
| 끝난 커리어도 "이어하기"로 표시 | 은퇴 후 타이틀로 이동 | `ui.js` `vTitle` | "지난 커리어 결과 보기"로 표시 |
| 시즌 기록의 소속이 승격 직후 값으로 남음 | 11월에 콜업된 해의 기록 | `engine.js` `offseason` | 그 시즌에 뛴 소속으로 기록 |

진행 불가, NaN, 범위를 벗어난 수치는 3,000회 시뮬레이션에서 나오지 않았습니다.

아직 남은 것(밸런스). 자동 진행 기준 수치이며, 사람은 더 잘합니다.

| 지표 | 값 | 판단 |
|---|---|---|
| 1군 데뷔 | 100% (평균 18.5세) | 초반에 실패할 여지가 없어 긴장이 약함 |
| 은퇴 나이 | 평균 31.7세 | 종목 특성에 비해 늦음. 후반 10년이 길게 늘어짐 |
| 1군 대회 우승 | 커리어당 2.95회 | 우승이 흔해 값어치가 떨어짐 |
| 포지션별 점수 | 지원 60.5 / 사수 51.3 | 반응속도 노쇠가 사수에게만 크게 작용 |
| 성향별 점수 | 두뇌형 57.8 / 노력형 52.1 | 노력형의 장점이 약함 |
| 부상 | 커리어당 0.59회 | 손목 관리가 거의 위협이 안 됨 |

밸런스는 수치만으로 정하면 안 되므로, 실제 플레이 반응을 받은 뒤 3단계와 묶어 조정합니다.

## 3. 이탈 위험이 있는 구간

- 첫 1~2년(연습생·2군): 경기가 없거나 의미가 작아 "계획 고르고 진행"만 반복합니다. 이 게임의 재미를 보여 주기 전에 20번 넘게 눌러야 합니다.
- 리그 달: 선택 없이 결과 표만 봅니다. 내가 키운 능력치가 경기에서 어떻게 작용했는지 보이지 않습니다.
- 20대 후반 이후: 능력치는 내려가고 새로운 사건이 줄어 같은 해가 반복됩니다.
- 첫 화면: 무엇을 목표로 무엇을 눌러야 하는지 알려 주는 안내가 없습니다.

## 4. 단계별 계획

| 단계 | 내용 | 기대 효과 | 난도 | 위험 | 테스트 기준 |
|---|---|---|---|---|---|
| 1 (완료) | 저장 안전장치, 테스트 확장 | 진행 상황 유실 방지, 이후 단계의 안전망 | 낮음 | 낮음 | 3,000회 통과, 저장 왕복·예전 저장·손상 복구 검사 통과 |
| 2 (완료) | 승부처: 플레이오프·결승·국제전의 경기 중 선택 | 육성 결과가 경기에서 체감됨 | 중간 | 시리즈 진행을 저장 가능한 형태로 변경 | 5절의 검증 결과 |
| 3 | 초반 속도와 밸런스 | 첫 시즌 이탈 감소 | 낮음 | 수치 변경이 전체 분포에 영향 | 데뷔율·은퇴 나이·포지션 격차 목표 범위 |

| 5 | 팬 반응: 경기 뒤 상황별 문장 조합(외부 AI 호출 없음) | 주목받는 느낌, 비용 0 | 낮음~중간 | 문장 반복 | 연속 10경기 내 같은 문장 없음 |

| 7 | 커리어 카드 이미지와 도전 과제 | 공유, 재도전 이유 | 중간 | 이미지 저장 방식의 브라우저 차이 | 안드로이드 크롬·iOS 사파리에서 저장 확인 |

순서를 바꾼 이유: 피드백의 2순위였던 라이벌보다 초반 속도(3단계)를 앞에 뒀습니다. 초반에 떠나는 사람은 라이벌을 만나지 못하기 때문입니다.

## 5. 2단계 결과: 승부처

구현한 것

- 일반 리그 경기는 그대로 빠르게 처리합니다.
- 준결승·8강·4강은 시리즈가 마지막 세트까지 갔을 때 승부처가 1회 나옵니다.
- 결승은 어느 한쪽이 매치 포인트인 세트마다 나오며 시리즈당 최대 3회입니다. 결승에 출전하면 최소 1회는 나옵니다.
- 국제전(미드시즌 컵, 월드 파이널, 네이션스컵)에도 같은 기준을 씁니다.
- 상황은 14종(`D.MOMENTS`)이고 선택지는 3개씩입니다: 개인 기량(피지컬·반응속도), 판단(판단력·멘탈), 조직력(팀워크·숙련 폭). 보정이 큰 선택일수록 기본 확률이 낮습니다.
- 성공 확률은 이벤트와 같은 `chance()`로 계산해 그대로 보여 주고, 그 숫자로 한 번 판정합니다. 선택지마다 성공·실패 시 세트 승률도 표시하며, 이 값은 실제 세트 계산식(`effStr`, `winP`)에서 나옵니다.
- 성공해도 세트를 질 수 있고 실패해도 이길 수 있습니다(아래 수치).
- 빠른 진행을 켜면 기대 세트 승률이 가장 높은 선택으로 자동 판단합니다. 승부처 화면에서도 "감독 판단에 맡긴다"로 자동 선택할 수 있습니다.
- 벤치이거나 부상 중이면 승부처가 나오지 않습니다.

구조 변경

- `series()`를 없애고 대진과 진행 위치를 `S.sim.tour`에 두는 방식으로 바꿨습니다(`runTour`). 한 달 처리는 `simMonth`(시작) → `runSim`(대회 진행, 승부처에서 멈춤) → `finishMonth`(마무리)로 나뉩니다.
- 장면 종류 `moment`(선택), `mresult`(결과)를 추가했습니다.
- 판정은 선택하는 순간 한 번 일어나고 바로 저장됩니다. 선택 전에 다시 불러오면 같은 승부처가 같은 확률로 나오고, 결과 화면에서 다시 불러와도 세트가 다시 진행되지 않습니다.
- 우승·수상·시즌 기록 처리는 대회가 끝난 뒤 `tourEnd`에서 한 번만 실행됩니다.
- `migrate()`에 `sim`, `recentMom` 기본값을 추가했습니다.
- 리그 경기 계산식과 성장·계약 규칙은 바꾸지 않았습니다.

검증 결과 (`node test/sim.js 3000`, 실행 시간 약 58초)

| 항목 | 결과 |
|---|---|
| 커리어 3,000회 은퇴까지 진행 | 통과. 상태 검사 약 165만 회, 진행 불가·NaN·범위 이탈 없음 |
| 승부처 도중 저장 → 불러오기 → 재개 | 45,538회 모두 같은 승부처로 재개 |
| 결과 화면에서 반복 불러오기 | 세트 스코어와 경기 수가 변하지 않음 |
| 1단계에서 만든 실제 저장 4종(`test/fixtures`) | 각 20회씩 80회 모두 은퇴까지 진행 |
| 승부처 없는 리그 경기 | 승률 49.00% → 48.30%, 평균 평점 6.756 → 6.715, 평점 구간별 차이 최대 0.86%p (기준 1%p 이내). 실행마다 승률이 48.3~48.8% 사이에서 달라짐 |
| 표시 확률과 실제 성공률 | 개인 기량 51.3% → 51.1%, 판단 60.1% → 59.9%, 조직력 59.5% → 59.6% (기준 2%p 이내, 넘으면 테스트 실패) |
| 승부처 세트 승률 | 성공 뒤 표시 67.9% / 실제 68.0%, 실패 뒤 표시 35.3% / 실제 34.9% |
| 1군 대회 우승 | 커리어당 3.00 → 3.42 (+14%, 기준 +20% 이내) |
| 폰 크기 390×844 헤드리스 크롬 | 1단계 저장으로 이어하기 → 승부처 → 새로고침 후 같은 승부처 → 결과 → 새로고침 → 월간 보고까지 확인. 가로 넘침·스크립트 오류 없음 |

처음 구현에서는 선택 성공률이 63~72%여서 1군 대회 우승이 29% 늘었습니다. 모든 선택지의 기본 확률을 12 낮춰 위 수치로 맞췄습니다.

확인하지 못한 것

- 실제 폰 기기, iOS 사파리, 삼성 인터넷, 배포된 주소(github.io)
- 웹 글꼴이 적용된 화면(테스트 환경에서 글꼴을 내려받지 못함)
- 사람이 직접 했을 때 선택이 재미있는지, 문장이 자연스러운지

남은 문제

- 자동 진행 기준으로 우승과 올해의 선수가 조금 늘었습니다(올해의 선수 경험 10.4% → 12.4%). 3단계 밸런스 조정에서 함께 다룹니다.
- 시리즈의 킬/데스/어시스트는 세트 합계로 표시되어 단판 경기보다 크게 보입니다.
- 승부처는 내가 출전한 시리즈의 51%에서 나옵니다. 준결승이 2-0으로 끝나면 나오지 않습니다.
- 같은 상황이 최근 6회 안에 반복되지 않게 했지만, 14종이라 긴 커리어에서는 다시 보게 됩니다.

## 5-1. 다음 작업 제안: 3단계 초반 속도와 밸런스

3단계로 넘어갈 수 있는 상태입니다. 저장 호환과 회귀 테스트가 갖춰졌고 2단계 검증이 모두 통과했습니다.

- 목표: 1군 데뷔 80~90%, 평균 은퇴 28~30세, 포지션별 점수 차 5점 이내, 1군 대회 우승 커리어당 2회 안팎
- 연습생·2군 기간에 선택과 사건을 더 넣어 첫 20번의 진행이 비지 않게 하기
- 변경 파일: `js/engine.js`(성장·노쇠·승격 기준 수치), `js/data.js`(초반 이벤트), `test/sim.js`(목표 범위 검사)
- 수치만으로 정하기 어려우므로 직접 플레이한 반응을 먼저 받는 것이 좋습니다.

## 6. 단계별 작업 지시문

다음 단계를 맡길 때 그대로 쓸 수 있는 문장입니다.

- 3단계: "docs/roadmap.md 5-1절대로 초반 속도와 밸런스를 조정해 줘. 목표는 1군 데뷔 80~90%, 평균 은퇴 28~30세, 포지션별 점수 차 5점 이내. 바꾼 수치와 전후 비교표를 PR에 적어 줘."
- 4단계: "연습생 동기 라이벌을 추가해 줘. 이름·포지션·소속·능력치·전적·관계가 저장되고 은퇴까지 유지돼야 해. 예전 저장도 열려야 해."
- 5단계: "경기 뒤 팬 반응을 문장 조합 방식으로 추가해 줘. 외부 API는 쓰지 말고, 반복 검사를 test/sim.js에 넣어 줘."
- 6단계: "첫 3개월 안내와 우승 연출을 추가해 줘. 건너뛰기가 가능해야 하고 움직임 줄이기 설정을 따라야 해."
- 7단계: "은퇴 화면을 이미지 한 장으로 저장하는 커리어 카드와 도전 과제를 추가해 줘."
