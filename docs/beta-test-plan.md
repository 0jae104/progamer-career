# 비공개 베타 테스트 계획

대상: 아는 사람 10~30명에게 주소를 직접 전달하는 소규모 비공개 시험. 공개 베타와 다릅니다(공개 베타는 `docs/release-checklist.md`의 차단 항목이 풀린 뒤).

**이 문서는 계획과 양식입니다. 아직 참가자를 모으지 않았고, 수집한 응답도 없습니다.** 아래 "예상"이라고 적힌 것은 개발하는 쪽의 가설이며 결과가 아닙니다. 결과를 적을 때는 맨 아래 "결과 기록" 절에 실제 응답만 적습니다.

자동 수집은 하지 않습니다. 게임에는 분석 도구가 없고, 참가자의 기록은 참가자가 직접 보내 준 것만 받습니다.

**진입 판정(2026-11-21, v0.11.2): 조건부 가능.** 아직 시작하지 않습니다. v0.11.0에서 경기 흐름(전략 선택, 관전, 소리)이 바뀌었으므로, 비공개 베타에 앞서 `docs/stage11-phone-playtest.md`의 3분 체험과 질문 네 가지를 본인과 몇 사람에게 먼저 해 보기를 권합니다.

| 구분 | 상태 |
|---|---|
| 코드·자동 검사 준비 | **완료** (알려진 P0 0건. `docs/stage10-2-qa-report.md`) |
| 실제 배포 주소 확인 | **미실행** |
| 실제 폰 확인 | **기록된 것 없음** (세 브라우저 모두 0 / 66, 핵심 12항목도 0 / 12. 소유자가 폰에서 정상 작동을 확인했다고 알려 왔으나 항목별 결과는 받지 못함) |

"조건부"의 조건은 8절의 4~6번입니다: 배포 주소에서 새 버전과 예전 저장 확인, 실제 폰 한 대 이상에서 핵심 12항목 통과(P0 0건), 답을 받을 곳과 기한. 셋이 채워지면 시작하고, 그 전에는 시작하지 않습니다. 확인 중 P0(저장 손실, 실행 불가, 복원 실패)가 하나라도 나오면 **보류**로 바뀝니다. (10-1단계 문서에서는 같은 상태를 "보류"라고 적었습니다. 조건과 남은 일은 그때와 같고, 이번 요청서의 세 단계 표기에 맞춰 이름만 바꿨습니다.)

## 0. 모집과 개인정보

- 인원: 10~30명. 처음에는 3~5명에게 먼저 보내 P0 문제가 없는지 본 뒤 나머지에게 보냅니다.
- 대상: 직접 아는 사람. 가능하면 안드로이드와 아이폰이 섞이게, 이 장르(5대5 팀 게임)를 아는 사람과 모르는 사람이 섞이게 합니다.
- 공개된 곳(커뮤니티, SNS)에 주소를 올리지 않습니다. 그것은 공개 베타이며 `docs/release-checklist.md` 0절이 풀린 뒤의 일입니다.
- 받는 정보는 최소로 합니다: 기기 종류와 브라우저, 설문 답, 본인이 보내 준 캡처와 백업 파일. 이름·연락처·나이는 묻지 않습니다. 기록표에는 이름 대신 번호를 씁니다.
- 백업 파일에는 선수 아이디와 게임 기록만 들어 있습니다. 받은 파일은 문제를 확인한 뒤 지웁니다. 다른 사람에게 넘기지 않습니다.
- 설문 도구(구글 설문 등)를 쓰면 그 도구가 이메일 주소 같은 정보를 모을 수 있습니다. "이메일 수집 안 함"으로 설정하고, 참가자에게 어떤 도구인지 알립니다.
- 게임에는 분석·광고 도구와 로그인을 넣지 않습니다.

## 0-1. 모집할 때 보내는 글 (복사해서 씁니다)

```
혼자 만들고 있는 웹 게임을 15분만 해 봐 줄 수 있을까?

프로게이머 한 명의 커리어를 연습생부터 은퇴까지 키우는 게임이야.
설치 없이 폰 브라우저에서 바로 열려. 가입도 광고도 없고, 기록은 네 폰 안에만 저장돼.

부탁할 것은 두 가지야.
1) 15분 정도 해 보기 (아래 순서)
2) 끝나고 질문 몇 개에 답하기 (5분)

아직 시험판이라 기록이 사라질 수 있어. 이상한 화면이 나오면 캡처해서 보내 주면 큰 도움이 돼.
주소는 다른 곳에 올리지 말아 줘.

주소: https://0jae104.github.io/progamer-career/
답 보낼 곳: (여기에 적기)
언제까지: (여기에 적기)
```

보내기 전에 "답 보낼 곳"과 "언제까지"를 채웁니다. 이어서 1절의 안내문과 2절의 15분 과제를 함께 보냅니다.

## 1. 참가자에게 보내는 안내문

아래를 그대로 복사해 보낼 수 있습니다.

```
"프로게이머 키우기"(가제) 비공개 시험에 참여해 주셔서 감사합니다.

주소: https://0jae104.github.io/progamer-career/
설치 없이 폰 브라우저에서 바로 열립니다. 크롬, 삼성 인터넷, 사파리 어느 것이든 됩니다.

미리 알아 둘 것
- 아직 만드는 중인 게임입니다. 오류가 있을 수 있습니다.
- 진행 상황은 지금 쓰는 폰의 그 브라우저 안에만 저장됩니다. 브라우저 데이터를 지우거나
  시크릿 창으로 열면 사라집니다. 업데이트 과정에서 사라질 가능성도 있습니다.
  아끼는 기록은 기록실 → 백업에서 파일로 내려받아 두세요.
- 게임은 여러분의 정보를 어디로도 보내지 않습니다. 아이디 칸에 실명이나 연락처는 쓰지 마세요.
- 부탁드리는 것은 두 가지입니다. 15분 과제(필수)와 30분 과제(선택). 끝나면 아래 질문에 답해 주세요.
- 이상한 점을 보면 화면을 캡처해 주세요. 가장 큰 도움이 됩니다.
- 기한: (날짜)   답을 보낼 곳: (연락처 또는 설문 주소)
```

## 2. 15분 첫 플레이 과제 (필수)

참가자에게는 설명하지 않고 과제만 줍니다. 막히는 곳이 어디인지 보기 위해서입니다.

1. 주소를 열고 새 커리어를 시작한다. 포지션은 마음에 드는 것으로 고른다.
2. 첫 시즌이 끝날 때(11월 스토브리그 화면)까지 진행한다. 15분이 지나면 거기서 멈춘다.
3. 멈춘 시점을 적는다: 몇 년차 몇 월이었는지, 연습생·2군·1군 중 어디였는지.

참가자가 적어 보낼 것
- 쓴 기기와 브라우저(예: 갤럭시 S23, 삼성 인터넷)
- 고른 포지션과 그 이유 한 줄
- 15분 뒤 도달한 시점
- 중간에 "뭘 해야 할지 모르겠다"고 느낀 순간이 있었다면 어느 화면이었는지
- 그만두고 싶었던 순간이 있었다면 언제, 왜

## 3. 30분 장기 플레이 과제 (선택)

1. 15분 과제에서 이어서, 또는 새로 시작해서 30분 더 진행한다. 맨 아래 "▶▶ 자동진행"을 써도 된다(썼다면 적는다).
2. 플레이오프에서 승부처가 나오면 직접 고른다. 기억나는 승부처 상황을 두세 개 적는다.
3. 은퇴까지 갔다면 커리어 카드를 만들어 저장해 본다.
4. 기록실 → 백업에서 백업 파일을 내려받아 본다. 가능하면 다른 브라우저에서 복원해 본다.

참가자가 적어 보낼 것
- 도달한 시점(몇 년차, 소속, 은퇴했다면 등급)
- 같은 승부처 상황을 두 번 이상 봤는지. 봤다면 대략 몇 번, 지루했는지
- 승부처에서 고른 것이 결과에 영향을 줬다고 느꼈는지
- 카드 저장과 백업이 되었는지, 파일을 어디서 찾았는지

## 4. 설문

5점 척도(1 전혀 아니다 ~ 5 매우 그렇다)와 한 줄 이유. 구글 설문 같은 도구로 옮겨 써도 되고, 메시지로 받아도 됩니다. 설문 도구를 쓰면 그 도구의 개인정보 수집(이메일 등)을 참가자에게 알려야 합니다.

| # | 질문 | 형식 |
|---|---|---|
| 1 | 포지션을 고르기 쉬웠다 | 1~5 + 이유 |
| 2 | 포지션 설명을 읽고 그 자리가 무슨 일을 하는지 알 수 있었다 | 1~5 |
| 3 | 처음 10분 동안 지금 무엇을 목표로 해야 하는지 알 수 있었다 | 1~5 + 헷갈린 화면 |
| 4 | 화면의 글자와 버튼이 폰에서 보기·누르기 편했다 | 1~5 + 불편했던 화면 |
| 5 | 같은 상황이 반복되어 지루했다 | 1~5 + 어떤 상황 |
| 6 | 승부처의 선택이 실제로 중요하다고 느꼈다 | 1~5 |
| 7 | 승부처에서 세 선택지의 차이(위험과 보상)를 이해할 수 있었다 | 1~5 |
| 8 | 내 포지션만의 특색을 느꼈다 | 1~5 + 고른 포지션 |
| 9 | 계약 제안 화면에서 어느 팀을 고를지 판단할 정보가 충분했다 | 1~5 / 해당 화면을 못 봄 |
| 10 | 저장·백업·복원을 어렵지 않게 할 수 있었다 | 1~5 / 해 보지 않음 |
| 11 | 다른 포지션으로 다시 해 보고 싶다 | 1~5 |
| 12 | 이 게임을 친구에게 보여 주고 싶다 | 1~5 |
| 13 | 가장 재미있었던 순간 | 자유 |
| 14 | 가장 답답하거나 지루했던 순간 | 자유 |
| 15 | 오류나 이상한 화면을 봤다면 | 자유 + 캡처 |
| 16 | 그만두고 싶었던 순간이 있었다면 언제, 왜였나(없었으면 "없음") | 자유 |
| 17 | 15분 과제 뒤에 더 했는가. 했다면 얼마나, 하지 않았다면 이유 | 자유 |

## 5. 운영하는 쪽이 기록할 것 (수동)

참가자 한 명당 한 줄. 참가자의 이름 대신 번호를 씁니다.

| 번호 | 기기·브라우저 | 포지션 | 15분 뒤 시점 | 첫 시즌 완료(예/아니오) | 멈춘 곳과 이유 | 30분 과제 참여 | 은퇴까지 감 | 반복 체감(Q5) | 재플레이 의향(Q11) | 보고한 오류 수 |
|---|---|---|---|---|---|---|---|---|---|---|
| | | | | | | | | | | |

모은 뒤 볼 것
- 첫 시즌 완료 비율과, 완료하지 못한 사람이 멈춘 화면
- 15분 안에 그만두고 싶었던 순간이 몰리는 구간
- 포지션별 Q8(특색)과 Q11(재플레이)
- Q5(반복)에서 4 이상을 준 사람이 본 상황
- 같은 오류가 몇 명에게서 나왔는지, 기기·브라우저가 겹치는지

표본이 10~30명이면 비율의 오차가 큽니다(10명 중 7명이면 실제 비율은 대략 40~90% 사이 어디든 될 수 있습니다). 숫자보다 "어디서 막혔는가"를 읽는 데 씁니다.

## 6. 개발하는 쪽의 예상 (가설, 결과 아님)

시험 전에 적어 둡니다. 결과와 비교하기 위해서입니다.

- 예상 1: 연습생 기간(첫 시즌 대부분)이 경기가 없어 심심하게 느껴질 수 있다.
- 예상 2: "코치 평가", "감독 신뢰"와 콜업 조건의 관계를 처음에는 이해하기 어려울 수 있다.
- 예상 3: 승부처는 2군 플레이오프에 가야 처음 나오므로 15분 과제에서는 못 보는 사람이 많을 것이다.
- 예상 4: iOS 사파리에서 PNG와 백업 파일이 어디에 저장됐는지 찾기 어려울 수 있다.
- 예상 5: 정글·서폿처럼 장르 용어가 낯선 사람은 포지션 설명을 펼쳐 읽어야 이해할 것이다.

자동 진행으로 잰 참고 수치(사람의 결과가 아님): 20번 진행한 뒤 소속은 연습생 약 21%, 2군 약 78%, 1군 약 1%입니다. 한 커리어에서 승부처는 평균 13~14번 나옵니다.

## 7. 오류 보고

`docs/mobile-qa.md` 맨 아래의 문제 보고 양식을 씁니다(심각도 P0·P1·P2 포함). 참가자에게는 "어느 화면에서, 무엇을 눌렀더니, 어떻게 됐는지"와 캡처만 부탁하고, 양식은 운영하는 쪽이 채웁니다.

P0(저장이 사라짐, 진행 불가)이 한 건이라도 나오면 시험을 멈추고 원인을 먼저 찾습니다.

참가자에게 보낼 짧은 신고 양식(복사해서 보냅니다)

```
이상한 점을 보셨다면 아래만 적어 보내 주세요. 캡처가 있으면 가장 좋습니다.

1. 폰과 브라우저: (예: 갤럭시 S23, 삼성 인터넷)
2. 어느 화면에서: (예: 월간 보고, 계약 제안, 기록실)
3. 무엇을 눌렀더니:
4. 어떻게 됐는지:
5. 다시 해도 똑같은가: (예 / 아니오 / 모름)
6. 타이틀 화면 맨 아래 숫자: (예: v0.11.0)

기록이 사라졌거나 게임이 멈췄다면 브라우저 데이터를 지우지 말고 그대로 두고 알려 주세요.
기록실 → 백업 → 내려받기가 되면 그 파일도 함께 보내 주시면 원인을 찾을 수 있습니다.
```

## 8. 진입 조건과 판정

비공개 베타(아는 사람 10~30명)의 조건입니다. 공개 베타의 조건(`docs/release-checklist.md` 0절의 여섯 항목)과 다릅니다. 제목 확정, 상표 검색, 개인정보 안내문의 법률 검토, 세 브라우저 66항목 전부는 비공개 베타의 조건이 아닙니다.

| # | 조건 | 상태(2026-11-21) | 근거 |
|---|---|---|---|
| 1 | 데이터 손실·진행 불가 문제 0건(알려진 것 기준) | 충족(자동 검사 기준) | 시뮬레이션 3,000회, 화면 검사, 갱신 검사 통과. `docs/stage10-2-qa-report.md` |
| 2 | 핵심 흐름(새 커리어, 저장·이어하기, 은퇴, 백업·복원)의 검사 증거 | 충족(자동 검사 기준, PC 헤드리스 크롬) | 같은 보고서 2절 |
| 3 | 결제·개인정보 관련 치명 문제 0건 | 충족 | 결제·계정·분석 도구가 없음. 외부 요청은 호스팅과 글꼴뿐(`docs/release-checklist.md` 4절) |
| 4 | 배포 주소에 v0.11.0이 올라가 있고, 예전 저장이 남는다 | **미실행** (GitHub의 배포 기록상 v0.10.1까지 배포 성공. 사이트 접속 확인은 아님) | `docs/deployment-verification.md` D-1 ~ D-5를 브라우저 한 종류 이상에서 |
| 5 | 실제 폰 한 대 이상에서 핵심 12항목 통과, P0 0건 | **미실행** | `docs/phone-check-12.md` |
| 6 | 답을 받을 곳과 기한을 정함 | **미정** | 소유자 |
| 7 | 참가자에게 "저장이 사라질 수 있다"와 백업 방법을 안내 | 준비됨 | 1절 안내문 |

**판정: 조건부 가능.** 4, 5, 6번이 남아 있습니다. 채워지기 전에는 시작하지 않습니다. 모두 소유자가 폰 한 대로 30~40분이면 할 수 있는 일입니다. 셋이 채워지면 처음 3~5명에게 보내는 것으로 시작합니다.

5번을 안드로이드에서만 했다면 아이폰 참가자에게는 "아이폰에서는 아직 확인하지 못했다"고 알리고 받습니다(그 반대도 같습니다). 그 참가자의 첫 보고가 곧 그 기기의 첫 실기기 결과가 됩니다.
