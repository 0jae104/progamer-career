## 1. 변경 요약

### 화면 순서 (정상 상태)

1. 선수 프로필·OVR
2. 컨디션 / 손목 / 코치 평가(감독 신뢰) / 인기
3. 보유 자금(누르면 자산 탭)
4. **목표**(접힌 두 줄 요약: 올해 목표 / 다음 목표. 누르면 조건별 막대와 설명)
5. 이번 달 할 일
6. 이번 달 라이벌전(있는 달만)
7. 지난 진행의 핵심 결과
8. 아래 탭, 진행 / 자동진행 / 멈춤

저장 실패 경고와 새 버전 안내가 있을 때는 그것이 목표 위에 옵니다(안전상 예외).

### DOM 구조

```
.stagebg
  header.lower                  선수 프로필·OVR
  div#hbox                      상태 네 칸(.hstat) + 보유 자금(.moneyrow)   ← 자동진행이 달마다 안쪽을 통째로 바꿈
  main.content
    div#gbox                    목표(.goal) 하나                             ← 글이 달라진 달에만 안쪽을 바꿈
    section.plansec             이번 달 할 일
    button.rvcard               (라이벌전이 있는 달만)
    div.recap                   지난 진행
  footer.foot                   탭, 진행 버튼
```

- 목표를 `#hbox` 안에 넣지 않았습니다. 그 상자는 달마다 통째로 바뀌므로 목표가 사라지거나 펼친 상태가 접힙니다. 요청서의 권고대로 **자금 상자 바로 다음의 독립된 상자**에 두었습니다.
- 목표 칸은 한 곳에서만 그립니다(`tPlay()`의 맨 앞). CSS `order`나 `position`으로 옮기지 않았으므로 보이는 순서, 키보드 순서, 화면 읽기 순서가 같습니다.
- 펼침 여부는 화면 상태(`U.goalOpen`)가 기억하므로 달이 넘어가도, 다른 탭에 다녀와도 유지됩니다.

### 수정한 파일

| 파일 | 내용 |
|---|---|
| `js/ui.js` | `goalLine()`이 `#gbox` 상자를 그리고 안쪽은 `goalIn()`. `tPlay()`의 순서 변경. `apTick()`이 목표 상자의 안쪽을 갱신(글이 같으면 건드리지 않음)하고, 상자·칸이 하나씩인지 확인. 접힌 요약을 두 줄로("목표" 이름표를 첫 줄 안에). 자동진행 중의 입력 처리(아래) |
| `css/style.css` | 요약 두 줄 배치 |
| `test/browser/apdom.js` | 달마다 목표 칸 수·순서·글을 엔진과 대조, 펼친 채 달리기, 달리는 중 할 일 바꾸기 |
| `test/browser/play.js`, `test/static.js` | 순서 검사 갱신 |
| 버전 파일, `test/browser/update-chain.js`, `measure.js` | 0.11.7, v0.11.6 → v0.11.7 갱신 단계 |

### 함께 바꾼 동작 하나

자동진행 중에 **이번 달 할 일**이나 **목표**를 누르면, 전에는 자동진행만 멈추고 누른 것은 무시됐습니다(한 번 더 눌러야 함). 이제 **멈추면서 바로 적용**됩니다. 요청서의 "홈의 월간 행동 변경도 계속 한 번의 터치로"에 맞춘 것이고, 다른 입력은 전과 같이 멈추기만 합니다. 자동진행은 계속 달리지 않고 멈춥니다(다시 누르면 재개).

### 나빠진 점 (요청한 순서의 대가)

- 목표가 올라온 만큼 그 아래가 내려갔습니다. **라이벌전이 있는 달의 라이벌전 줄**이 키가 작은 폰에서 첫 화면 밖으로 나갑니다.
  - 320×568: 줄의 위쪽 64px(제목)만 보이고 나머지는 스크롤. v0.11.6에서는 다 보였습니다.
  - 375×667(iPhone SE 2·3세대 크기, 따로 측정): 줄 전체가 아래 버튼에 가려져 스크롤해야 보입니다. v0.11.6에서는 대부분 보였습니다.
  - 360×800, 390×844, 430×932: 전처럼 다 보입니다.
  - 이 때문에 `play.js`의 기존 검사 하나를 320px에서만 "줄 전체가 보인다" → "제목 줄이 보인다"로 바꿨습니다. 통과시키려고 기준을 낮춘 것이 맞고, 순서를 지키는 한 피할 방법을 찾지 못했습니다. 라이벌 팀과의 경기에서는 자동진행이 멈추고 경기 준비 화면에 같은 정보가 나오므로 정보가 사라지지는 않습니다.
- 목표를 펼치면(막대 포함 250px 안팎) 할 일이 아래로 내려가 320×568에서는 스크롤이 필요합니다. 접으면 돌아옵니다.

## 3. 자동진행 검사 (`node test/browser/run.js apdom`, 확인 152개 통과)

자동진행이 한 달 넘어갈 때마다 화면에서 직접 센 값입니다.

| 경우 | 진행 | 다시 시작 | 자금 버튼 | 목표 칸 | 순서(자금→목표→할 일) 어긋난 달 | 목표 요약이 엔진과 다른 달 | 멈춤 버튼이 가려진 달 |
|---|---|---|---|---|---|---|---|
| 390×844 1군, 자동 관리 6종, 멈춤·재개, 자산 탭 왕복, 달리는 중 할 일 바꾸기 | **24개월** | 5번 | 항상 1 | 항상 1 | 0 | 0 | 0 |
| 320×568 1군, 자동 관리 6종, 같은 조작 | **30개월** | 8번 | 항상 1 | 항상 1 | 0 | 0 | 0 |
| 390×844 2군, **목표를 펼쳐 둔 채** | **25개월** | 9번 | 항상 1 | 항상 1 | 0 | 0 | 0 |
| 320×568 2군, 목표를 펼쳐 둔 채 | 13개월 | 4번 | 항상 1 | 항상 1 | 0 | 0 | 0 |
| 375×812 2군, 자동 관리 끔 | 13개월 | 5번 | 항상 1 | 항상 1 | 0 | 0 | 0 |
| 430×932 1군, 자동 관리 3종 | 10개월 | 1번 | 항상 1 | 항상 1 | 0 | 0 | 0 |

- 요청서의 1·2·6·12·24개월은 위 진행에 들어 있습니다(달마다 셌습니다).
- **목표의 진척**: 요약의 글(올해 목표 이름과 진행, 다음 목표 이름과 "달성 수/조건 수")을 달마다 엔진의 `goalNow()`·`goal()`과 대조했습니다. 달리는 동안 요약이 3~10가지로 바뀌었고(예: 3/14경기 → 4/14경기) 모두 일치했습니다.
- **펼쳐 둔 목표**는 달리는 동안 접히지 않았고 막대 수가 조건 수와 같았습니다. 접어 둔 목표는 펼쳐지지 않았습니다.
- **진행 줄(`#apline`)과 자금 줄(`#apcash`)** 은 달마다 각각 하나였습니다. 상태 영역과 `#hbox`·`#gbox`도 하나씩입니다.
- **할 일 칸의 위치**는 접힌 상태에서 달리는 동안 고정(390: 333px, 320: 251px)이거나 목표 글의 줄 수가 바뀔 때 19px 안에서 움직였습니다.
- **달리는 중 할 일 바꾸기**: 한 번 눌러 스크림 → 솔랭으로 바뀌고 자동진행이 멈췄습니다.
- 멈춘 이유에 시즌 결산, 경기 준비(라이벌 팀 포함), 사건이 들어 있고, 처리한 뒤 다시 시작했습니다.
- **정산**: 여섯 경우 모두 처음 잔고 + 내역 합 = 마지막 잔고, 달마다도 일치, 적히지 않은 변동 0. `extras.js`의 3,170달 대조도 그대로 통과. 경제 규칙은 건드리지 않았습니다.
- **v0.11.5의 결함이 검사에 잡히는지**: `node test/browser/repro.js` — 옛 코드에서 자금 줄 2→3→…→10개가 다시 재현됐습니다(검사 방법이 유효함).
- 처음 안내(튜토리얼)의 목표 설명은 `flow` 묶음이 처음부터 플레이하며 지나갑니다(통과). 안내 중에는 전처럼 목표가 펼쳐져 보입니다.
