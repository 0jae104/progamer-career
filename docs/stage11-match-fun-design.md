# 11단계 설계: 경기 한 판의 재미 (v0.11.0)

작성일 2026-11-21. 이번 단계는 기능을 늘리는 것이 아니라 **토너먼트 한 시리즈를 "준비 → 선택 → 관전 → 승부처 → 결과"로 이어지는 한 판으로 만드는 것**입니다. 포지션 변경(예전 11단계 계획)은 뒤로 미뤘습니다.

검증하려는 질문은 하나입니다. **"내가 고른 선택이 경기에서 느껴지고, 결과에 이유가 있으며, 다음 경기가 궁금해지는가."** 이 문서는 무엇을 만들었고 왜 그렇게 만들었는지를 적습니다. 재미가 실제로 생겼는지는 사람이 해 봐야 알 수 있고, 아직 아무도 해 보지 않았습니다(`docs/stage11-phone-playtest.md`).

## 1. 무엇이 달라졌나

| | v0.10.2 | v0.11.0 |
|---|---|---|
| 토너먼트 시리즈의 시작 | 알림 없이 계산됨 | **경기 준비 화면**: 상대, 대회 단계, 몇 선승, 내 컨디션, 전력으로 본 세트 승률, 라이벌과 상대 전적 |
| 경기 전 선택 | 없음 | **전략 3종 중 하나**(또는 전략 없이). 실제 세트 승률에 반영 |
| 세트 진행 | 보이지 않음. 승부처가 나오면 스코어만 표시 | **관전**: 세트가 하나씩 드러남. 빠르게 / 바로 결과 가능 |
| 승부처 | 창이 새로 뜸 | 같은 창 안에서 이어짐. 진입할 때 긴장감 있는 소리 |
| 시리즈 결과 | 월간 보고의 한 줄 | **결과 요약**: 승패, 내 전략과 세트별로 승률을 몇 %p 바꿨는지, 내 평점·K/D/A·MVP, 다음 단계 |
| 소리 | 없음 | 효과음 10종(직접 합성), 켜기/끄기 |
| 3분 체험 | 없음(16세 연습생부터 시작) | 타이틀의 **경기 체험하기**: 1군 토너먼트 시리즈 직전부터 |

화면에 나오는 것은 전부 장면에 저장된 실제 기록입니다. 없는 사건(선취점, 특정 팀원의 킬, 오브젝트)은 만들지 않았습니다. 관전 문구는 "1세트를 가져왔다", "매치 포인트다", "벼랑 끝이다"처럼 세트 스코어에서 바로 나오는 말만 씁니다.

## 2. 왜 토너먼트 시리즈인가 (범위를 정한 이유)

실제 코드의 경기 흐름은 두 가지입니다.

- **정규 리그**: `simMonth()`가 한 달 치 경기를 한꺼번에 계산해 월간 보고로 보여 줍니다. 경기 전에 "이번 상대는 누구"라고 멈추는 지점이 없습니다.
- **토너먼트**(플레이오프, 미드시즌 컵, 월드 파이널, 네이션스컵): `runTour()`가 대진을 `S.sim.tour`에 두고 **세트 단위로** 진행합니다. 승부처에서 멈췄다가 이어 가는 구조가 이미 있고, 도중 저장·재개도 검증되어 있습니다.

그래서 **내가 출전하는 토너먼트 시리즈**에만 적용했습니다. 리그 경기를 같은 방식으로 바꾸려면 월 단위 계산을 경기 단위로 뜯어고쳐야 하고, 그러지 않고 화면만 붙이면 없는 대진을 지어내게 됩니다. 리그 경기는 예전 그대로입니다. 이 제약은 코드 주석(`js/engine.js`의 "경기 전 전략" 머리말)에도 적어 두었습니다.

한 커리어에 이런 시리즈는 평균 18~19번 나옵니다(자동 진행 400 커리어에서 전략 선택 장면 7,456회). 벤치에서 지켜본 시리즈에는 나오지 않습니다(예전처럼 월간 보고에 "벤치"로 적힙니다).

## 3. 전략: 무엇에, 얼마나 영향을 주는가

### 판정에 들어가는 자리

세트 승패는 예전과 똑같이 `playGame()`에서 난수 한 번으로 정해집니다. 전략은 그 직전에 **팀 전력에 더하는 보정** 하나입니다(`tacS()` → `effStr()`의 `mod.s`. 승부처의 세트 보정과 같은 자리).

- 난수를 쓰지 않습니다. 보정은 세트 스코어, 전력 차, 내 컨디션에서 계산됩니다.
- 절댓값 상한은 전력 1.6(`D.BAL.tac.cap`). 세트 승률로는 **최대 약 ±6%p**입니다(측정된 최댓값 6%p).
- 내 평점·K/D/A 계산에는 직접 넣지 않았습니다(세트를 이기고 지는 것을 통해서만 간접적으로 바뀝니다).
- 그 시리즈가 끝나면 사라집니다. 전략은 시리즈 상태(`S.sim.tour.cur.tac`) 안에 있고, 시리즈가 끝나면 그 상태 자체가 없어집니다.

### 세 가지 전략

| 전략 | 유리할 때 | 불리할 때 | 수치(전력) |
|---|---|---|---|
| 강하게 압박한다 | 세트 스코어가 앞서거나 동률. 컨디션이 좋을수록 큼 | 세트를 내줘 뒤질 때 | 앞서거나 동률: 0.5 + (컨디션 − 60) / 20, −0.5 ~ +1.5 / 뒤질 때: −1.2 |
| 안정적으로 운영한다 | 전력이 앞서는 상대(세트 승률 55% 이상) | 전력이 밀리는 상대(45% 이하) | 우세 +1.0 / 비슷 +0.3 / 열세 −0.8 |
| 상대 실수를 노린다 | 전력이 밀리는 상대, 세트를 뒤지고 있을 때 | 전력이 밀리지 않는데 동률이거나 앞설 때 | 뒤질 때 +1.6 / 열세 +0.8 / 동률 −0.4 / 앞설 때 −0.9 |

전력 1은 승률 50% 근처에서 약 3.6%p입니다.

### 실제로 그렇게 작동하는가 (측정)

`node test/tactics.js 400 24`: 실제 커리어에서 모은 시리즈 직전 상태 400개마다, 같은 난수 시드 24개로 전략만 바꿔 시리즈를 치렀습니다(시리즈 38,400회).

| 상황 | 전략 없음 | 강하게 압박 | 안정 운영 | 실수 노리기 |
|---|---|---|---|---|
| 전체 | 51.4% | 52.0% | 51.5% | 53.3% |
| 전력 우세(세트 승률 55% 이상) | 81.0% | 80.8% | **84.2%** | 80.9% |
| 비슷(45~55%) | 56.3% | 57.9% | **58.2%** | 56.5% |
| 전력 열세(45% 이하) | 26.4% | 27.4% | 23.7% | **30.3%** |
| 컨디션 70 이상 | 50.9% | **53.7%** | 50.8% | 52.8% |
| 컨디션 50 미만 | 50.9% | 48.6% | 51.5% | **52.9%** |

(시리즈 승률. 굵은 글씨가 그 상황에서 가장 높은 것)

- 상황을 읽고 고르면 시리즈 승률이 3~4%p 오릅니다. 잘못 고르면 2~3%p 내려갑니다(열세에서 안정 운영, 컨디션이 나쁠 때 압박).
- 항상 정답인 전략은 없습니다. 다만 **"실수 노리기"가 전체 평균에서 가장 높습니다**(+1.9%p). 이 표본에 전력 열세인 시리즈가 절반쯤이기 때문입니다. 사람이 해 본 뒤 한쪽으로 쏠리면 수치를 다시 봐야 합니다. 이번에는 더 손대지 않았습니다.
- 숫자가 작습니다. 의도한 크기입니다("작지만 확인할 수 있는 영향"). 한 판에서 체감되는지는 화면의 표시(경기 전 1세트 승률, 결과의 세트별 %p)에 달려 있고, 이것은 사람이 판단할 부분입니다.

### 고르지 않으면 예전과 같다

- "전략 없이 시작한다", 빠른 진행(승부처처럼 전략도 묻지 않음), 자동 진행, 예전 저장의 진행 중 시리즈는 보정이 0입니다.
- 엔진만으로 400 커리어를 은퇴까지 돌린 최종 상태의 해시가 v0.10.2와 같습니다(`278bb76e5b497353`). 판정과 난수 소비 순서가 바뀌지 않았다는 뜻입니다.
- 전략을 고르면 그 뒤의 난수 흐름이 달라지므로 커리어는 다르게 흘러갑니다. **이것은 의도한 게임성 변화입니다.**

## 4. 한 판의 흐름과 화면

엔진의 장면은 네 가지입니다. `prematch`(신규) → `moment` → `mresult`(둘은 예전 그대로) → `match`(신규). 화면은 이 넷을 **한 장의 창**으로 그립니다. 같은 시리즈 안에서는 창이 다시 올라오지 않고 내용만 바뀝니다.

1. **경기 준비**(`prematch`): 팀 약칭과 구단 색, 스코어판, 걸린 것("지면 이 대회는 여기서 끝난다" / 결승이면 "이기면 우승이다"), 내 포지션·컨디션·전력으로 본 세트 승률, 라이벌이 있으면 닉네임과 통산 전적. 전략마다 유리·불리 한 줄씩과 **그 전략으로 치를 때의 1세트 승률**이 보입니다. 전략을 누르면 시작 버튼이 켜집니다.
2. **관전**: 판정은 "경기 시작"을 누르는 순간 엔진이 끝냅니다(승부처가 나오면 거기까지만). 화면은 아직 보여 주지 않은 세트를 1.15초 간격으로 하나씩 드러냅니다. 전선 표시가 이긴 쪽으로 밀리고, 세트마다 소리가 납니다. **빠르게**(0.38초 간격), **바로 결과**(또는 "바로 승부처로")가 있습니다. 3전제는 3~5초, 5전제는 길어야 7초쯤입니다.
3. **승부처**(`moment`): 예전의 포지션별 승부처 50종 + 공통 14종 그대로입니다. 고르기 전에는 그 세트와 시리즈의 결과가 정해지지 않았으므로 보일 수도 없습니다. 표시되는 세트 승률에는 전략이 반영되어 있고, 그렇게 적혀 있습니다.
4. **승부처 결과**(`mresult`): 성공·실패, 그 세트의 승패, 전략이 그 세트를 몇 %p 바꿨는지.
5. **결과 요약**(`match`): 승패와 다음 단계 / 내 전략과 세트별 영향 / 승부처에서 고른 것 / 내 평점·K/D/A·MVP / 라이벌 통산 전적 / 버튼 하나. 자세한 성적과 팬 반응은 이어지는 월간 보고에 예전 그대로 있습니다.

관전 연출은 장면에 `seen` 표시를 남깁니다. 새로 고치거나 다시 그려도 같은 연출이 두 번 나오지 않습니다(우승 연출과 같은 방식).

### 판정과 연출의 분리

- 화면(`js/ui.js`)은 엔진의 `resolve()`를 **선택할 때 한 번**만 부릅니다. 관전 속도, 건너뛰기, 소리는 화면 상태(`U.watch`)에만 있고 엔진을 부르지 않습니다.
- 소리의 잡음은 고정된 수열로 만듭니다. 게임 난수를 쓰지 않습니다.
- 검사: 같은 상태·같은 시드·같은 전략에서 "엔진만 / 끝까지 관전 / 빠르게 / 바로 결과 / 음소거" 다섯 경로의 결과·기록·자금·컨디션·라이벌 전적이 글자 단위로 같습니다(`test/browser/match.js` B).

### 알려진 한계 (예전부터 있던 것)

게임은 난수의 "위치"를 저장하지 않습니다. 그래서 시리즈 도중에 새로 고치면 **이미 치른 세트는 그대로지만, 아직 치르지 않은 세트는 새로 고치지 않았을 때와 다르게 나올 수 있습니다.** v0.10.2의 승부처도 같았습니다. 이미 정해진 결과가 바뀌거나 두 번 적용되는 일은 없습니다(검사로 확인).

## 5. 소리

참고한 게임에서 좋았다고 한 것은 "소리의 개수"가 아니라 "긴장 → 선택 → 반응 → 해소"가 들린다는 점이었습니다. 그래서 큐를 이 순서에 맞췄습니다.

| 순간 | 큐 | 느낌 |
|---|---|---|
| 전략 선택, 소리 켜기 | `tap` | 낮고 짧은 확인 |
| 경기 시작 | `start` | 0.6초의 전환(낮은 음이 올라오며 열림) |
| 세트를 가져옴 / 내줌 | `setw` / `setl` | 두 음 올라감 / 내려감 |
| 승부처 진입 | `tension` | 세 번 올라가는 낮은 음 |
| 승부처 성공 / 실패 | `ok` / `fail` | 밝은 4음 / 부드럽게 내려가는 한 음 |
| 시리즈 승리 / 결승 승리 / 패배 | `win` / `winbig` / `lose` | 짧은 팡파르 / 더 긴 팡파르와 환호 같은 잡음 / 낮은 두 음 |

전부 `js/ui.js` 안에서 Web Audio로 합성합니다. 음원 파일이 없어서 저작권·용량·오프라인 보관·버전 혼합 문제가 생기지 않습니다. 배경음은 넣지 않았습니다(피로와 품질을 장담할 수 없어서). 자세한 것은 `docs/audio-assets.md`.

## 6. 3분 체험: 경기 체험하기

타이틀의 **경기 체험하기**를 누르면 실제 엔진이 새 선수를 만들어 1군 토너먼트 시리즈 직전까지 자동으로 진행한 뒤 경기 준비 화면에서 멈춥니다. 포지션·지역·성향은 누를 때마다 달라집니다.

- **완전히 격리됩니다.** 백업 검사(`dryRun`)가 쓰는 것과 같은 방식으로 저장소를 메모리 상자로 바꿔 놓고 돌립니다. 체험 중의 저장·명예의 전당·도전 과제 쓰기는 그 상자 안에서 끝납니다. 진행 중인 커리어와 난수도 떼어 두었다가 끝나면 되돌립니다.
- 시리즈를 이기면 다음 라운드가 이어지고, 대회가 끝나면(또는 "체험 끝내기"를 누르면, 또는 새로 고치면) 타이틀로 돌아옵니다.
- 본편과 같은 코드입니다. 체험에서만 작동하는 연출은 없습니다.
- 검사: 끝까지 / 도중에 끝내기 / 도중 새로 고침 세 경우 모두 여섯 저장 키와 진행 중인 커리어 상태가 글자 단위로 그대로입니다.

## 7. 저장과 호환

- **저장 키는 그대로**입니다. 새로 생긴 것은 소리 설정을 담는 `pg_opt_v1` 하나이고, 커리어 저장·백업·복원과 무관합니다(백업 파일에 들어가지 않습니다).
- 커리어 저장 안에서 늘어난 것: 진행 중인 시리즈 상태의 `tac`, `sets`, `shown`, 그리고 새 장면 두 종류. 모두 선택 항목이라 예전 저장은 그대로 열립니다.
- v0.10.2에서 시리즈 도중에 저장한 파일을 열면 그 시리즈는 예전 방식으로(전략을 묻지 않고, 결과 장면 없이) 끝나고, 다음 시리즈부터 새 흐름이 나옵니다.
- **되돌릴 때 주의**: v0.11.0에서 경기 준비·관전·결과 창이 떠 있는 채로 저장된 커리어를 v0.10.2로 열면, v0.10.2는 그 장면을 몰라 **버튼이 없는 빈 창**을 보여 주고 진행할 수 없습니다(실제 v0.10.2 코드로 확인. 저장 데이터는 그대로이고 엔진은 정상으로 엽니다). 그래서 v0.11.0에 문제가 있어도 v0.10.2로 되돌리기보다 **고쳐서 v0.11.1로 올리는 것**을 권합니다. 그 밖의 시점에 저장된 파일은 양쪽에서 열립니다. v0.11.0부터는 모르는 장면에 "넘어간다" 버튼을 보여 주므로 앞으로의 버전에서는 이 문제가 생기지 않습니다. `docs/deployment-verification.md` 7절에 적었습니다.

## 8. 참고한 것과 가져오지 않은 것

| 참고한 설계 원리 | 여기서 한 것 |
|---|---|
| 선택 → 상성 → 경기에서 확인 (Teamfight Manager) | 전략 3종과 상황별 득실, 결과에서 세트별 영향 표시 |
| 나중에도 기억나는 사건 (RimWorld) | 새 사건을 만들지 않고, 이미 쌓이는 기록(라이벌 통산 전적, 승부처에서 고른 것)을 경기 전후에 보여 줌 |
| 경기장의 긴장감과 소리 (Rising Fighter) | 긴장 → 선택 → 반응 → 해소에 맞춘 효과음, 세트가 하나씩 드러나는 관전 |

화면, 문구, 그림, 소리, 이름은 어느 것도 가져오지 않았습니다. 참고 게임의 자산을 본 적도, 흉내 낸 적도 없습니다(소리는 음 높이와 길이를 직접 정한 합성음입니다).

## 9. 아직 재미가 부족할 것 같은 곳 (정직한 추측)

사람이 해 보기 전의 추측입니다.

1. **관전이 단순합니다.** 세트 스코어와 전선 표시뿐입니다. 한 세트 "안"에서 무슨 일이 있었는지는 없습니다(엔진이 세트 안의 사건을 만들지 않기 때문에 지어낼 수 없습니다). 재미의 핵심이 여기라면 세트 안의 흐름을 판정 시점에 기록하는 작업이 다음 단계입니다.
2. **전략의 영향이 작습니다.** 최대 6%p는 한 판에서는 운에 묻힙니다. 결과 화면의 숫자로 "이유"는 보이지만 "터지는" 느낌은 약할 수 있습니다.
3. **승부처가 없는 시리즈**(2:0, 3:0)는 선택이 경기 전 한 번뿐입니다.
4. **경기 준비 화면이 깁니다.** 390px 폰에서 시작 버튼까지 한 번 내려야 합니다.
5. **리그 경기는 그대로입니다.** 커리어의 대부분을 차지하는 정규 시즌에는 이 흐름이 없습니다.
6. **첫 토너먼트까지 오래 걸립니다.** 본편에서는 연습생·2군을 거쳐야 합니다. 그래서 체험하기를 만들었지만, 본편의 초반 자체는 달라지지 않았습니다.
