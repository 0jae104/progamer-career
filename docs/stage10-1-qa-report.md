## 5. 찾은 문제와 고친 것

### 문제 1 (P0급 위험, 재현됨): 탭 두 개를 쓰면 뒤처진 탭이 최근 진행을 지운다

- **재현**: 자동 검사에서 실제 v0.10.0 소스로 재현했습니다(`update-chain` 3-1). v0.10.0 탭과 다른 탭이 같은 커리어를 연 상태에서 다른 탭이 세 번 진행한 뒤, v0.10.0 탭에서 한 번 진행하자 저장이 "v0.10.0 탭이 알던 상태 + 1"로 바뀌고 다른 탭의 세 번이 사라졌습니다. 엔진 단위에서도 보호를 끄면 같은 일이 일어납니다(`test/sim.js` 10-1이 실패).
- **같은 원인으로 생길 수 있는 일**(코드로 판단, 따로 재현하지는 않음): 한 탭에서 커리어를 지우고 새로 시작해도 뒤처진 탭이 한 번 진행하면 지운 커리어가 되살아나고 새 커리어가 사라집니다. 폰에서는 "브라우저 탭 + 홈 화면 아이콘"이나 "며칠 전에 열어 둔 탭"으로 같은 상황이 됩니다.
- **원인**: 각 탭이 자기 메모리의 상태를 통째로 저장하고, 저장하기 전에 저장소가 그 사이 바뀌었는지 보지 않음. 다른 탭의 변경을 알리는 처리도 없었음.
- **고친 것**(`js/engine.js`, `js/ui.js`): 엔진이 "이 탭이 마지막으로 읽거나 쓴 커리어 저장의 원문"을 기억함. 저장·삭제·새 커리어 직전에 저장소의 값이 그것과 다르면 쓰지 않음. 화면은 `storage` 이벤트, 탭으로 돌아올 때, 버튼을 누를 때 이를 확인해 "다른 탭에서 진행됐다" 창을 띄우고 다른 조작을 받지 않음. "최근 저장 불러오기"는 페이지를 새로 고침. 경기 계산과 난수는 건드리지 않음. 저장 형식도 그대로.
- **재검증**: `test/sim.js` 10-1(11개), `tabs` A~D, `update-chain` 3-1. 보호를 꺼 보면 검사가 실패하는 것도 확인함("바뀐 저장을 알아채지 못함").
- **남은 한계**
  - 이미 열려 있는 v0.10.0 탭에는 이 장치가 없습니다. 그 탭이 새로 고쳐지기 전에 진행하면 덮어씁니다. 새 버전 탭은 이를 알아채고 멈추므로 두 탭이 번갈아 덮어쓰는 일은 없고, 저장이 망가지지도 않습니다(검사로 확인). 잃을 수 있는 것은 "새 탭에서 한 최근 진행"입니다.
  - 커리어 저장만 봅니다. 명예의 전당과 도전 과제는 쓸 때마다 저장소에서 다시 읽어 더하는 방식이고 기록마다 ID가 있어 따로 막지 않았습니다.
  - 두 탭이 정확히 같은 순간에 쓰는 경우(수 밀리초)는 막지 못합니다. 사람이 두 탭을 동시에 누르기는 어렵습니다.
  - 저장소 접근이 막힌 브라우저(일부 사생활 보호 설정)에서는 탭끼리 저장을 공유하지 않으므로 해당 없습니다.

### 문제 2 (문서): 점검 순서가 내 기록을 지울 수 있었다

- `docs/mobile-qa.md`의 준비 1번이 "사이트 데이터를 지웁니다"였는데, 평소 게임을 하던 브라우저에서 그대로 하면 커리어와 명예의 전당이 지워집니다. 경고가 없었습니다.
- 고친 것: 맨 앞에 "시작하기 전에: 내 기록을 지키는 방법"을 넣고 준비 1번에서 그 절을 먼저 읽게 함. 배포 검증 문서도 검증용 프로필을 쓰게 함.

### 문제 3 (검사 스크립트): `positions` 묶음의 실패 2건

- **증상**: 첫 전체 실행에서 "320 gun: 검사용 상황을 만들지 못함"과 그 뒤의 시간 초과.
- **원인 1**: 검사가 페이지 안에서 `localStorage.clear()`로 저장소를 직접 비운 뒤 새 커리어를 만드는데, 새 보호 장치가 이것을 "다른 탭이 저장을 지움"으로 보고 새 커리어를 막았습니다. 게임이 아니라 검사 준비 과정의 문제입니다. 검사가 저장소를 직접 바꾼 뒤 엔진에 알리도록 고쳤습니다(`PG._seen()`, 검사용).
- **원인 2**(다시 돌리다 발견): "전용 승부처 창에 '컨디션'이 보여야 한다"는 확인이 v0.10.0에서 추가된 컨디션 없는 상황(`sup_swap`)에 걸리면 실패했습니다. 브라우저 검사는 난수 시드를 고정하지 않아 그 상황이 먼저 나올 때만 실패하는, 10단계부터 있던 불안정한 확인입니다(10단계의 실행에서는 우연히 걸리지 않았습니다). "컨디션이 걸린 상황에서만 보이고, 아닌 상황에서는 보이지 않는다"로 고쳤습니다.
- **재검증**: `positions` 3회 연속 122 / 122.

### 고치지 않은 것

- 서비스 워커, 오프라인, 백업·복원, 연타 방지, 공유·저장 실패 경로에서는 재현되는 문제를 찾지 못했습니다. 그래서 건드리지 않았습니다.
- "새 버전이 준비됐다"는 알림은 넣지 않았습니다. 온라인에서는 새로 고침만으로 새 버전이 뜨고, 실제 주소에서 어떻게 보이는지 확인한 뒤에 판단할 일입니다.
