# 배포 주소 검증 절차 (GitHub Pages)

대상: https://0jae104.github.io/progamer-career/

**이 문서의 절차는 아직 한 번도 실행되지 않았습니다(2026-11-20, v0.10.1 기준).** 개발 환경에서는 배포 주소에 접속할 수 없고(접속이 차단됨), GitHub Pages 설정도 읽을 수 없었습니다. 자동 검사가 확인한 것은 "같은 파일을 로컬 서버에 올렸을 때의 동작"입니다. 실제 주소에서의 결과는 아래 순서대로 사람이 확인해 8절의 표에 적어야 합니다.

걸리는 시간: PC만 20분, 폰까지 40분 정도.

## 0. 알아 둘 것

- **게임 저장**(커리어, 명예의 전당, 도전 과제)은 브라우저의 localStorage에 있습니다. 주소(출처)마다, 브라우저마다 따로입니다.
- **파일 보관본**(오프라인용)은 Cache Storage에 있고 이름이 `pg-career-버전`입니다. 서비스 워커(`sw.js`)가 새 버전을 받으면 예전 보관본만 지웁니다. localStorage는 건드리지 않습니다.
- 그래서 "캐시 삭제"는 저장을 지우지 않지만, 브라우저의 **"사이트 데이터 삭제" / "쿠키 및 사이트 데이터 삭제"는 둘 다 지웁니다.**
- 온라인이면 항상 서버의 최신 파일을 먼저 받습니다. 새 버전은 보통 새로 고침 한두 번으로 뜹니다. GitHub Pages는 파일을 몇 분간 캐시하므로 배포가 끝난 직후에는 최대 10분쯤 예전 버전이 보일 수 있습니다.
- 검증은 **평소에 게임을 하지 않는 브라우저 프로필**에서 합니다. PC 크롬이면 오른쪽 위 프로필 → "추가"로 새 프로필을 만들면 됩니다. 평소 쓰는 프로필에서 해야 한다면 먼저 기록실 → 백업 → 내려받기를 합니다.
- 시크릿 창은 쓰지 않습니다(서비스 워커와 저장이 평소와 다르게 동작합니다).

## 1. 병합하기 전에: 예전 버전에서 데이터 만들기

**갱신 검증은 "예전 버전이 깔린 상태"에서 시작해야 의미가 있습니다. 그래서 이 절은 새 버전의 PR을 병합하기 전에 합니다.** 이미 병합했다면 이 절을 건너뛰고 2절부터 하되, 8절 표의 "예전 버전에서 올라옴" 칸은 `미실행`으로 둡니다(다음 배포 때 할 수 있습니다).

1. 검증용 프로필(폰이면 검증용 브라우저)에서 배포 주소를 엽니다.
2. 타이틀 맨 아래의 버전 숫자를 적습니다(예: v0.10.0). → 표의 "배포 전 버전"
3. 새 커리어를 만들어 은퇴까지 갑니다(기록 탭의 "빠른 진행"을 켜면 5~10분). 명예의 전당에 한 명이 생깁니다.
4. 타이틀로 나와 새 커리어를 하나 더 만들고 열 달쯤 진행한 뒤 그대로 둡니다. 선수 아이디, 나이, 몇 월인지 적습니다.
5. 기록실에서 명예의 전당 인원과 도전 과제 달성 개수를 적습니다.
6. 기록실 → 백업 → 내려받기로 백업 파일을 하나 받아 둡니다(문제가 생겼을 때 되돌릴 수단이자, 버전 간 복원 검증에 씁니다).
7. 새로 고침을 한 번 해서 서비스 워커가 설치되게 합니다. PC라면 F12 → Application → Service Workers에 `sw.js`가 "activated"인지, Cache Storage에 `pg-career-0.10.0` 하나가 있는지 봅니다.
8. 가능하면 **이 탭을 닫지 말고 게임 화면(이어하기를 누른 상태)에 둔 채로** 다음 절로 갑니다. 5절에서 "예전 버전 탭"으로 씁니다.

## 2. 병합과 배포 확인

1. GitHub에서 PR의 검사(Actions)가 초록색인지 확인하고 병합합니다.
2. 저장소 → Actions 탭에서 "pages build and deployment"(또는 Pages 배포 워크플로)가 방금 병합한 커밋으로 끝났는지 봅니다. 저장소 → Settings → Pages에서 어느 브랜치·폴더를 배포하는지도 한 번 확인해 표에 적습니다.
3. 병합 커밋 번호 앞 7자리와 배포가 끝난 시각을 적습니다.
4. 새 탭에서 `https://0jae104.github.io/progamer-career/sw.js?check=1`을 엽니다(`?check=` 뒤 숫자를 바꿔 가며). 여섯째 줄쯤의 `const VERSION = '0.10.1';`이 새 버전이면 서버에 올라온 것입니다. 예전 숫자면 몇 분 뒤 다시 봅니다.

## 3. 갱신: 예전 버전 → 새 버전

검증용 프로필에서, **새 탭**으로 합니다(1절 8번의 예전 탭은 그대로 둡니다).

1. 배포 주소를 엽니다. 타이틀 아래 버전이 새 숫자인지 봅니다. 예전 숫자면 새로 고침을 한 번 더 합니다. 몇 번 만에 바뀌었는지 적습니다.
2. "게임 파일을 다 받지 못했거나 예전 파일이 섞여 있다" 안내가 뜨면 "새로 고침"을 누르고, 그것으로 해결됐는지 적습니다. 이 안내 자체는 실패가 아닙니다(섞인 채로 게임이 돌지 않게 막는 장치). 새로 고침을 여러 번 해도 사라지지 않으면 실패입니다.
3. "이어하기"에 1절 4번의 선수가 같은 나이·같은 달로 보이는지 봅니다. 눌러서 한 달 진행합니다.
4. 기록실 → 명예의 전당 인원, 도전 과제 개수가 1절 5번과 같은지 봅니다. 은퇴한 선수의 상세와 커리어 카드를 엽니다.
5. PC: F12 → Application → Cache Storage에 `pg-career-0.10.1` 하나만 남았는지, Local Storage에 `pg_career_v1`, `pg_legacy_v1`, `pg_ach_v1`이 있는지 봅니다.
6. 1절 6번에서 받은 **예전 버전의 백업 파일**을 기록실 → 백업 → "백업 파일 고르기"로 골라 미리 보기가 정상인지 봅니다. 복원까지 눌러 보려면 지금 상태의 백업을 먼저 하나 더 받아 둡니다.

## 4. 오프라인

1. PC: F12 → Network → "Offline"을 켜고 새로 고침. 폰: 비행기 모드를 켜고 다시 엽니다.
2. 타이틀이 뜨고 "오프라인 상태다" 안내와 새 버전 숫자가 보이는지 봅니다.
3. 이어하기 → 한 달 진행 → 기록실 → 커리어 카드 만들기까지 해 봅니다.
4. 오프라인을 끄고 새로 고침해 정상인지, 3번에서 진행한 한 달이 남아 있는지 봅니다.
5. 폰에서 홈 화면에 추가한 아이콘이 있다면 그것으로도 1~4를 합니다. (iOS는 홈 화면 앱과 사파리의 저장이 따로일 수 있습니다. 따로면 실패가 아니라 "분리됨"으로 적습니다.)

## 5. 탭 여러 개, 예전 버전 탭

v0.10.1부터는 다른 탭이 저장을 바꾸면 오래된 탭이 멈추고 "다른 탭에서 진행됐다" 창을 띄웁니다.

1. **새 버전 탭 두 개**: 탭 A와 탭 B에서 모두 이어하기. A에서 한 달 진행. B로 가면 창이 떠 있어야 합니다(안 떠 있으면 아무 버튼이나 눌러 봅니다. 그때 떠야 합니다). "최근 저장 불러오기" → 이어하기 → A와 같은 달인지 봅니다.
2. **예전 버전 탭**(1절 8번에서 남겨 둔 탭): 이 탭은 예전 코드라 보호 장치가 없습니다. 여기서 한 달 진행하면 새 탭의 최근 진행을 덮어씁니다. 이것은 알려진 한계입니다. 확인할 것은 두 가지입니다.
   - 새 버전 탭으로 가면 "다른 탭에서 진행됐다" 창이 뜬다.
   - 예전 탭을 닫고 새 버전 탭에서 "최근 저장 불러오기" → 이어하기를 하면 오류 없이 열리고 계속 진행된다(저장이 망가지지 않았다).
3. 예전 탭을 새로 고침하면 새 버전이 되는지 봅니다.

## 6. 캐시만 지우기

1. PC 크롬: 설정 → 개인정보 및 보안 → 인터넷 사용 기록 삭제 → **"캐시된 이미지 및 파일"만** 체크하고 삭제합니다. "쿠키 및 기타 사이트 데이터"는 체크하지 않습니다.
2. 배포 주소를 다시 열어 이어하기·명예의 전당·도전 과제가 그대로인지 봅니다.
3. (선택) F12 → Application → Storage → "Clear site data"에서 **Local and session storage의 체크를 푼 뒤** 나머지만 지우고 같은 것을 봅니다.

"쿠키 및 사이트 데이터"까지 지우면 저장도 사라집니다. 이것은 브라우저의 동작이며 게임이 막을 수 없습니다. 그래서 검증용 프로필에서만 합니다.

## 7. 롤백 (새 버전에 문제가 있을 때)

증상이 "화면이 열리지 않음", "이어하기가 안 됨", "저장이 사라짐" 가운데 하나면 바로 되돌립니다.

1. GitHub에서 병합한 PR을 열고 아래쪽의 **Revert** 버튼을 누릅니다. 되돌리는 PR이 만들어집니다. 검사가 끝나면 병합합니다.
   - 명령으로 하려면: `git revert -m 1 <병합 커밋>` 후 push.
2. Actions에서 Pages 배포가 끝나기를 기다린 뒤 2절 4번처럼 `sw.js`의 버전이 예전 숫자로 돌아갔는지 봅니다.
3. 검증용 프로필에서 새로 고침 → 타이틀의 버전이 예전 숫자인지, 이어하기가 되는지 봅니다.
4. 이용자 쪽에서는 따로 할 일이 없습니다. 온라인에서 한두 번 새로 고치면 되돌린 버전을 받습니다.

알아 둘 점

- v0.10.0과 v0.10.1은 저장 형식이 같습니다. v0.10.1에서 진행한 저장은 v0.10.0으로 되돌려도 열립니다(v0.10.0 탭이 쓴 저장을 v0.10.1이 여는 방향은 자동 검사로 확인했고, 반대 방향은 형식이 같다는 점에 근거한 판단입니다. 실제로 되돌려 본 적은 없습니다).
- 저장 형식에 새 항목을 넣은 버전을 되돌릴 때는 다릅니다. 새 버전에서 만든 저장이 예전 코드에서 열리는지 먼저 확인해야 합니다. 그런 버전을 낼 때 이 절에 주의 사항을 추가합니다.
- 되돌려도 **이미 지워진 저장은 돌아오지 않습니다.** 저장이 사라지는 문제가 보고되면, 그 이용자에게 브라우저를 건드리지 말고(사이트 데이터 삭제 금지) 기록실 → 백업이 열리는지 먼저 확인해 달라고 합니다. `pg_career_v1_bak`(시즌 시작 시점 사본)과 `pg_career_v1_bad`(손상된 원본)가 남아 있을 수 있습니다.
- 되돌린 뒤 고쳐서 다시 낼 때는 버전 숫자를 새로 올립니다(예: 0.10.2). 같은 숫자로 다른 내용을 내지 않습니다.
