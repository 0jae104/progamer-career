# 프로게이머 키우기

열여섯 연습생에서 월드 파이널까지, 선수 한 명의 커리어 전체를 살아 보는 육성 시뮬레이션 웹 게임입니다. 설치 없이 폰과 PC 브라우저에서 실행됩니다.

### 화면 쓰는 법 (v0.11.2)

- **플레이** 탭: 이번 달 할 일 다섯 칸(솔랭·스크림·분석·휴식·방송)이 항상 보이고 한 번 눌러 바꿉니다. 그 아래에 다음 목표 한 줄과 지난 진행 요약.
- 맨 아래 **▶ N월 진행**은 한 달, **▶▶ 자동진행**은 달을 계속 넘깁니다. 처음 누르면 무엇을 맡기고 어디서 멈추는지 보여 준 뒤 시작합니다.
  - 대신 하는 것: 평범한 월간 보고 넘기기, 평범한 사건 선택(안정·균형·도전 중 고른 성향대로), 켰다면 컨디션이 낮을 때 휴식과 평범한 토너먼트 경기.
  - 항상 멈추는 곳: 계약·이적 제안, 스토브리그, 입단 테스트, 성장 카드, 시즌 결산, 콜업·강등·부상·우승 알림, 결승·국제전·라이벌 팀과의 경기, 한 번뿐인 사건, 돈을 써야 위험을 피할 수 있는 사건(그 밖에는 돈이 드는 선택지를 고르지 않고 넘어간다).
  - **Ⅱ 멈춤**을 누르거나, 다른 탭을 누르거나, 화면이 가려지면 바로 섭니다. 멈춘 이유와 대신 고른 것("자동 선택 n건")이 요약에 남습니다.
- **선수** 탭: 상태 네 가지와 능력치. **리그** 탭: 순위표, 올해 성적, 라이벌. **자산** 탭: 자금·계약과 투자·자동 관리. **기록** 탭: 소식, 최근 자동 선택, 통산 기록, 명예의 전당, 백업, 소리와 설정.
- **자동 관리**(자산 탭): 투자 항목마다 스위치를 켜 두면 월급을 받은 직후 알아서 삽니다. 남겨 둘 돈과 한 달 상한을 정할 수 있고, 모자라면 사지 않고 이유를 적습니다. 처음에는 전부 꺼져 있습니다.
- 타이틀의 **경기 체험하기**는 1군 토너먼트 한 경기를 바로 해 보는 비공식 체험전입니다(기록에 남지 않음).

## 게임 구조

- **진행**: 1년은 10개월(2~11월)입니다. 매달 계획 하나를 고르고 진행합니다.
  스프링(2~4월) → 미드시즌 컵(5월) → 서머(6~8월) → 네이션스컵(9월, 짝수 연차) → 월드 파이널(10월) → 시상식·스토브리그(11월)
- **커리어 경로**: 연습생 → 2군 → 1군 벤치 → 주전 → 국가대표 → 올해의 선수. 홈 화면의 "다음 목표"에 승격 조건과 현재 수치가 나옵니다. 모든 선수가 1군에 오르지는 못합니다.
- **포지션 5개**: 탑, 정글, 미드, 원딜, 서폿. 포지션마다 OVR에 들어가는 능력치 비중, 경기 영향력, 전성기 길이가 다르고, 승부처에서 그 포지션만의 상황이 나옵니다. 자세한 계산식은 `docs/position-design.md`.
- **능력치 6종**: 피지컬, 반응속도, 판단력, 팀워크, 멘탈, 숙련 폭. 포지션마다 비중이 다르고, 능력치마다 잠재력(한계)이 있습니다.
- **노쇠**: 반응속도가 20대 중반부터 가장 먼저 꺾이고, 판단력은 오래 남습니다.
- **라이벌**: 같은 날 입단한 연습생 동기 두 명이 성장하고, 콜업되고, 이적하고, 은퇴합니다. 상대 전적은 내가 출전한 공식전의 실제 결과로만 쌓이고, 선택에 따라 경쟁심과 존중이 달라집니다. 능력 탭의 라이벌 카드에서 볼 수 있습니다.
- **팬 반응**: 경기가 있던 달의 월간 보고에 그 달 기록에 근거한 팬 반응이 2~3줄 붙습니다. 난수를 쓰지 않아 경기 결과에는 영향이 없습니다.
- **처음 안내와 우승 연출**: 새 커리어의 첫 3개월 동안 목표·계획·보고 화면에 한 줄 안내가 붙습니다(건너뛰기 가능, 기록 탭에서 다시 보기). 우승하면 짧은 연출이 한 번 나오고, 기기의 움직임 줄이기 설정을 따릅니다.
- **경기 한 판(0.11.0)**: 내가 출전하는 토너먼트 시리즈(플레이오프·미드시즌 컵·월드 파이널·네이션스컵)가 시작될 때 경기 준비 화면이 나옵니다. 전략 셋(강하게 압박 / 안정 운영 / 상대 실수 노리기) 가운데 하나를 고르면 그 시리즈의 세트 승률에 실제로 반영됩니다(세트당 최대 약 ±6%p. 전력 차·컨디션·세트 스코어에 따라 유리한 전략이 다릅니다). 세트가 하나씩 진행되는 것을 보거나(빠르게 / 바로 결과) 승부처를 거쳐 결과 요약에서 전략이 세트별로 무엇을 바꿨는지 확인합니다. 정규 리그 경기와 "승부처·전략 맡기기"를 켠 경우에는 적용되지 않고, 고르지 않으면 판정은 예전과 같습니다. 효과음은 직접 합성한 10종이고 언제든 끌 수 있습니다.
- **승부처**: 플레이오프와 국제전의 마지막 세트, 결승의 매치 포인트 세트에서 경기 중 선택이 나옵니다. 성공 확률과 세트 승률 변화를 그대로 보여 줍니다. 공통 상황 14종과 포지션 전용 상황 50종(포지션마다 10종)이 있고, 전용 상황의 선택지에는 컨디션이나 감독 신뢰가 반영되기도 합니다. 창 위쪽에 그 세트에 걸린 것(몇 선승, 지금 몇 대 몇)이, 선택지마다 "큰 승부 / 승부 / 안전" 표시가 나옵니다. 최근에 본 상황 8개는 다시 나오지 않습니다.
- **포지션 해설**: 월간 보고에 그 달 가장 잘한(또는 가장 부진한) 경기의 킬·데스·어시스트·평점을 포지션의 눈으로 읽어 주는 한 줄이 붙습니다.
- **계약 제안 설명**: 이적·재계약 제안마다 구단 전력과 리그 순위, 내 OVR과의 차이, 옮긴 뒤 감독 신뢰와 주전 여부, 그 구단의 라이벌, 연봉 차이를 보여 줍니다.
- **선택 이벤트**: 성공 확률과 그 근거(능력치, 감독 신뢰)를 그대로 보여 줍니다. 실패가 이어지면 보정이 붙습니다.
- **관리**: 컨디션, 손목(부상), 감독 신뢰, 인기, 자금
- **스토브리그**: 성장 카드 선택, 재계약·이적·연봉 협상, 은퇴
- **은퇴 평가**: 5개 축 점수, 등급, 별칭, 명예의 전당
- **기록실**: 타이틀 화면의 "기록실" 또는 게임 안 기록 탭에서 엽니다.
  - 명예의 전당: 은퇴한 커리어를 최대 200명까지 상세 기록으로 보관합니다. 점수·우승·최근 은퇴순 정렬, 선수별 상세, 두 명 비교, 삭제(확인 창과 되돌리기)가 있습니다.
  - 도전 과제: 21종. 여러 커리어에 걸쳐 쌓이는 수집 요소이며 경기·능력치·연봉에는 영향이 없습니다.
  - 백업: 진행 중인 커리어, 시즌 시작 사본, 명예의 전당, 도전 과제를 JSON 파일 하나로 내려받고, 다른 기기나 브라우저에서 그 파일로 전체 복원합니다.
- **커리어 카드**: 은퇴 화면이나 명예의 전당 상세에서 은퇴 기록을 1080×1350 PNG 한 장으로 만들어 저장하거나, 지원하는 기기에서는 공유합니다.

진행 상황은 브라우저에 자동 저장되고, 시즌이 시작될 때마다 복구용 사본을 하나 더 남깁니다. 같은 브라우저에서 탭을 두 개 열어 같은 커리어를 진행하면, 뒤처진 탭은 저장을 덮어쓰지 않고 멈춘 뒤 "최근 저장 불러오기"를 안내합니다(0.10.1). 게임을 열어 둔 사이에 다른 탭이 새 버전을 받으면 열어 둔 탭에 "새 버전이 올라왔다"와 새로 고침 버튼이 보입니다(0.10.2). v0.10.0 이하로 열어 둔 탭에는 이 보호가 없으므로, 갱신 뒤에는 열려 있던 탭을 새로 고쳐 주세요. 저장(localStorage)과 오프라인용 파일 보관본(Cache Storage)은 서로 다른 곳이라, 보관본이 지워지거나 버전이 바뀌어도 저장은 남습니다. 브라우저에서 "사이트 데이터 삭제"를 하면 둘 다 지워집니다. 저장 형식에 필드를 추가할 때는 `js/engine.js`의 `migrate()`에 기본값을 넣어 예전 저장이 열리게 합니다.

## 저장과 백업

저장은 모두 이 기기의 이 브라우저(localStorage)에만 있습니다. 서버나 계정이 없으므로 브라우저 데이터를 지우면 사라지고, 시크릿 모드나 다른 기기에서는 보이지 않습니다.

| 키 | 내용 |
|---|---|
| `pg_career_v1` | 진행 중인 커리어(행동마다 자동 저장) |
| `pg_career_v1_bak` | 시즌 시작 시점의 복구용 사본 |
| `pg_career_v1_bad` | 손상되어 열지 못한 저장의 원본(백업 파일에는 넣지 않음) |
| `pg_hall_v1` | 예전 형식의 명예의 전당(상위 30명). 0.6.0 이전과의 호환을 위해 그대로 유지 |
| `pg_legacy_v1` | 명예의 전당 보관소(기록 ID, 은퇴 시각, 상세 기록. 최대 200명) |
| `pg_ach_v1` | 도전 과제 달성 상태 |
| `pg_tut_v1` | 처음 안내를 끝냈는지 |

백업 사용법

1. 기록실 → 백업 → "백업 파일 내려받기". `progamer-career-backup-날짜-시각.json` 파일이 다운로드 폴더에 들어왔는지 확인합니다.
2. 옮길 기기에서 게임을 열고 기록실 → 백업 → "백업 파일 고르기"로 그 파일을 고릅니다.
3. 파일의 내용(선수, 진행 시점, 명예의 전당 수, 도전 과제 수)과 지금 기기의 내용을 나란히 보여 줍니다. "덮어쓰고 복원한다"를 누르면 기기의 데이터가 파일의 내용으로 모두 바뀝니다. 합치지 않습니다.
4. 형식이 다르거나 손상된 파일, 3MB가 넘는 파일, 더 새로운 버전의 파일은 거부하고 기기의 데이터는 그대로 둡니다. 복원 도중 저장에 실패하면 원래 데이터로 되돌립니다.
5. 복원 전에 파일 안의 커리어를 임시 공간에서 은퇴까지 자동으로 돌려 봅니다. 도중에 오류가 나는 파일은 복원하지 않습니다.

백업 파일 형식: `{ format: "progamer-career-backup", version: 1, app, exportedAt, payload: { career, careerBackup, hall, legacy, achievements, tutorialDone } }`

- 화면 검사는 저장소 폴더를 로컬 HTTP 서버로 띄워서 합니다. `file://`로 직접 연 화면은 브라우저의 저장 동작이 배포 환경과 달라 검사에 쓰지 않습니다.
- 헤드리스 크롬 한 종류로만 돌립니다. 실제 폰, iOS 사파리, 삼성 인터넷은 `docs/mobile-qa.md`로 사람이 확인해야 합니다.
- `.github/workflows/test.yml`: GitHub에 올리거나 PR을 열 때마다 문법 검사, 시뮬레이션 1,000회, 화면 검사, 갱신 검사가 자동으로 돕니다(약 9분, 공개 저장소는 무료). 결과는 저장소의 Actions 탭과 PR 아래쪽에 표시됩니다.
- 종료 코드가 0이 아니면 실패입니다. 실패한 항목이 한 줄씩 나옵니다.

## 배포와 업데이트

- 배포할 때는 버전을 여섯 곳에서 같이 올립니다: `js/engine.js`의 `VERSION`, `js/data.js`·`js/card.js`·`js/ui.js`의 파일 버전, `index.html`의 `?v=`와 확인 스크립트, `sw.js`의 `VERSION`. 하나라도 다르면 `test/sim.js`가 실패합니다. 타이틀 화면 아래에 버전이 보입니다.
- 서비스 워커(`sw.js`)는 설치할 때 그 버전의 파일을 한 번에 받아 두고, 온라인일 때는 항상 서버의 최신 파일을 씁니다. 오프라인이면 받아 둔 한 벌을 씁니다. 버전이 바뀌면 예전 보관본만 지우며, 게임 저장(localStorage)은 건드리지 않습니다.
- 업데이트 도중 연결이 끊겨 새 페이지에 예전 스크립트가 섞이면 게임을 시작하지 않고 "새로 고침" 안내를 띄웁니다.
- 서비스 워커는 배포 주소(HTTPS)와 `localhost`에서만 켜집니다.
- 주소(도메인, 사용자 이름, 저장소 이름)를 바꾸면 브라우저 저장이 분리되어 기존 이용자의 저장이 새 주소에서 보이지 않습니다. 바꾸기 전에 백업 안내가 필요합니다. 순서는 `docs/release-checklist.md` 6절에 있습니다.
- 로컬 서버와 GitHub Actions에서 확인한 것이며, 배포 주소(GitHub Pages)에서의 갱신은 직접 확인해야 합니다. 순서와 되돌리는 방법은 `docs/deployment-verification.md`에 있습니다. 예전 버전에서 올라오는 것을 보려면 **병합하기 전에** 그 문서의 1절부터 합니다.

## 고칠 때

- 난이도와 커리어 길이를 정하는 숫자는 `js/data.js`의 `D.BAL`에 모여 있고, 항목마다 뜻이 적혀 있습니다.
- 바꾼 뒤에는 `node test/sim.js 3000 --seed=1`을 돌립니다. 시드를 주면 같은 코드에서 같은 결과가 나와 전후를 비교할 수 있습니다. 오류, 저장 호환, 확률 검사에서 어긋나면 실패하고, 밸런스 목표(`D.BAL.target`)는 충족 여부만 표시합니다.
- 출력의 `PCT` 값을 `js/data.js`의 `D.PCT`에 옮깁니다(은퇴 화면의 상위 %).
- 포지션의 내부 ID(`van`, `rov`, `core`, `gun`, `sup`)는 저장 데이터에 들어 있으므로 바꾸지 않습니다. 화면 이름은 `D.ROLES`의 `name`이고, 예전 이름으로 저장된 기록은 `PG.roleLabel()`이 보여 줄 때만 바꿉니다.
- 승부처 상황을 추가할 때는 `D.MOMENTS`에 넣습니다. `role`을 적으면 그 포지션에서만 나옵니다. 수치 범위는 `docs/position-design.md` 4-1절을 따릅니다.
- 도전 과제를 추가할 때는 `js/data.js`의 `D.ACH`에 이름·설명을, `js/engine.js`의 `ACHV`에 같은 id의 판정식을 넣습니다. 판정식은 저장된 기록만 읽어야 합니다.
- 명예의 전당 기록이나 백업 파일의 형식을 바꿀 때는 `cleanRec`, `cleanLegacy`, `cleanAch`, `importCheck`를 함께 고치고 백업의 `version`을 올립니다.
- 화면에 값을 넣을 때는 `js/ui.js`의 `esc()`로 감쌉니다. 저장·장면·기록에서 온 값은 숫자라도 감쌉니다(`test/browser/security.js`가 모든 화면에 태그·따옴표가 든 문자열을 넣어 확인합니다).
- 장면에 새 항목을 추가하면 `js/engine.js`의 `SCENE` 규격에도 추가합니다. 진행 중 나온 장면이 규격에 맞지 않으면 `test/sim.js`가 실패합니다.

## 권리와 출처

- 게임에 나오는 리그, 구단, 선수, 대회 이름은 모두 창작입니다. 실제 게임·구단·선수의 이름, 로고, 이미지는 쓰지 않았습니다.
- 포지션 이름(탑·정글·미드·원딜·서폿)과 길·포탑·오브젝트·시야 같은 낱말은 여러 게임이 함께 쓰는 장르 용어입니다. 특정 게임의 캐릭터·기술·지도·대회 이름은 쓰지 않았습니다.
- 그림(도트 아바타, 아이콘)은 코드로 직접 그린 것입니다. 외부 이미지·음원·코드 라이브러리는 없습니다.
- 글꼴은 Google Fonts의 Black Han Sans, IBM Plex Sans KR입니다. 둘 다 SIL Open Font License라 상업적 이용이 가능합니다.
- 출시 전에 게임 제목과 구단 이름이 등록 상표와 겹치지 않는지 확인하세요(한국: 키프리스 kipris.or.kr).
- 이 저장소에는 오픈소스 라이선스를 붙이지 않았습니다. 코드는 공개되어 있지만 권리는 저장소 소유자에게 있습니다.
